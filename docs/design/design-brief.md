## 一、情绪基调（每条含原文出处）

| # | 基调 | 原文引用 | 出处 |
|---|---|---|---|
| 1 | **耗竭后的收口渴望**——用户不是来"逛"的，是被 10–22 分钟的决策拖垮后来自投降终结的 | 「现状参照基线 = 目标用户晚间决策 3–4 次/周·人，单次耗时 10–22 分钟、以「耗尽投降」收场（n=1 唯一行为证据）」；「唯一行为级证据为 18:12–18:58『22 分钟米线之夜』」 | 规划 §5 基线行、文档头 |
| 2 | **低能量**——晚间、疲惫、交互成本容忍度趋近于零 | 问题卡 P3「低能量零交互」（以此为准的五卡之一） | 规划文档头 |
| 3 | **要确定感，不要可选项**——一个答案就是产品的全部承诺 | 「30 秒、最多 5 次点击、只给你一个答案——而且它记得你爱吃什么」；「输出唯一结果（一道菜/品类 ＋ 一句情绪化推荐语）」 | 规划 §1 标题、§3 In-1 |
| 4 | **被记得的温度**——记忆层是产品唯一的"关系"资产 | 「而且它记得你爱吃什么」（§1 标题）；「差异化押注交互预算极限（≤5 步）＋ 个人味觉记忆 ＋ 成对约束，不拼餐厅数据」（§6 竞争行） | 规划 §1、§6 |
| 5 | **情绪化但不油腻**——推荐语本身是情绪载体，同时有克制的合规底线 | 「一句情绪化推荐语」（In-1）；「禁止输出健康/减脂类建议，加"特殊饮食需求请遵医嘱"免责说明」（§6 合规行） | 规划 §3、§6 |
| 6 | **诚实的工具感**——不装、不吆喝，数据最小化是人格的一部分 | 隐私口径「不要手机号、微信授权、位置」（FR-20/U8 文案，impl §4.2 合规件行）；假门「明示验证期免费、不展示虚假促销」 | impl §4.2；规划 §3 In-7 |

**基调总结一句**：一个深夜疲惫的人把"吃什么"这个决定交出来，产品要给他的是**确定、快、被记得、不打扰**——视觉必须第一秒就传递"这事归我们了"，而不是"快来逛"。

## 二、产品人格关键词（附出处）

1. **收口者（果断）**——「只给你一个答案」（§1 标题）；「稳态 2 次后强制收口」（In-1）。人格：替你拍板，不给你菜单。
2. **记得你的老友（记忆感）**——「它记得你爱吃什么」（§1 标题）；FR-09 隐式反馈沉淀。人格：有记性、有分寸。
3. **麻利（快而不糙）**——「≤30 秒 / ≤5 次点击，是硬性验收标准」（In-2）；「决策时长中位 ≤60 秒」（§5）。人格：不磨叽。
4. **诚实（有边界的暖）**——「禁止输出健康/减脂类建议」（§6）；假门诚实原则（评审 #3）。人格：只管口味，不装医生，不画饼。
5. **情绪同伴（口语、有锅气）**——「一句情绪化推荐语」（In-1）；固定标签池「想吃热乎 / 想吃冷的 / 想慢享」（In-4）。人格：说人话，带烟火气。

## 四、硬约束清单（逐条抄录＋设计含义）

### 4.1 埋点点位（FR-15 事件全集，impl §2.1 `events` 表 type 全集——埋点权威）

> 事件：会话起止 / 逐题作答与步数 / 弃答步位 / 接受 / 拒绝（负反馈） / 换一（含耗尽标记） / **跳转双事件（accept 侧＋jump 侧）** / 链接失效 / 回访曝光与应答（含自报下单） / 假门漏斗三事件（曝光→点击→登记） / 推荐曝光内容标识（7 日去重）。
> **设计含义**：每个事件必须有一个不可隐藏、不可合并的物理交互载体（按钮/点击/页面到达）。结果页四动作（accept/swap/re-ask/negative）一个都不能在视觉上降权到消失；「推荐曝光」随结果渲染自动触发，不得做"先骨架后内容"导致双计。

### 4.2 深链/兜底入口

- 「一键跳转外卖平台搜索该菜品……深链失效兜底 = 展示菜品名 ＋ 引导手动搜索」（规划 In-5）。
- 探活「全红且对照绿」→ 自动全局兜底＋P1（impl §5.2）；当晚会话自动带"链接失效"标。
- **设计含义**：跳转过渡与兜底页是常备路径而非异常路径，视觉上不许做成"报错脸"；兜底页仍要完成"给菜名"的核心交付。

### 4.3 性能预算（impl §2.3 延迟预算行＋规划 In-2/§5——全部为数字硬约束）

| 项 | 数值 | 设计含义 |
|---|---|---|
| 交互总预算 | ≤30 秒 / ≤5 次点击（硬验收）；时长中位 ≤60 秒 | 流程不得新增必要步骤；装饰动效不得吃掉作答时间 |
| 首屏 | P75 ≤2s（SSR 无 bundle） | 系统字体栈优先、零 Webfont 阻塞、CSS 内联可控 |
| 结果生成 | 池命中 P99 ≤1s；实时 P95 ≤3s / 硬超时 6s；LLM 单次 P95 ≤3s | 等待态按 ≤3s 设计；6s 硬超时必须有兜底落点 |
| 非 LLM API | P99 ≤500ms | 乐观 UI 空间小，按钮反馈即时但以真实响应为准 |
| 302 一跳 | P50 ≤300ms | 过渡帧短，不做"过场动画" |
| 30 秒分解 | 首屏 ≤2s＋作答 ≤15s＋等待 ≤3s＋缓冲 10s | 等待态预算只有 3 秒——动效上限 |

### 4.4 载体与技术形态

- H5（ADR-002）→ 终版 **P-c 微信外浏览器**（ADR-005：whattoeat.lifestyle，微信内硬拦截）＋ **PWA 可安装**（ADR-005 补强）。
- **Jinja2 SSR ＋ 原生 JS，无 SPA 构建链**（impl §1.1、HC-3、ADR-003 A 卡）。
- **设计含义**：① 微信内不可用＝分享话术/二维码场景全部指向"系统浏览器打开"；② PWA 主屏是留存生命线，引导条要有但不打断；③ 设计系统必须能落在无框架 SSR＋原生 JS 上——动效用 CSS 优先，避免重 JS 动画库。

### 4.5 产品立场红线

- **禁止无限浏览**：换一上限稳态 2 次/冷启动 3 次＋耗尽标记（In-1）；护栏 3 耗尽率红线（冷启动 >30% / 稳态 >20% → 生成质量回炉）。设计不许提供"再来一次"的无限路径。
- **"随便吧"口径**：投降式拍板不计北极星分子——弃答兜底（S7）视觉上要做"救场"，不做"诱导投降"。
- **健康边界**：禁健康/减脂表述＋"特殊饮食需求请遵医嘱"免责（FR-20，S1/S6 必现）。
- **假门诚实**：明示验证期免费、不虚构原价（FR-17，S12）。
- **数据最小化人格**：无账号、无位置、无手机号（S1 文案原文）；anon_id 可见可复制可清空（FR-11）。

### 4.6 Out 清单（规划 §3，逐条抄录——设计不得越界）

① 餐厅数据库、菜品数据库、评价体系、爬取对抗；② 用户自定义约束系统（完整 P4）；③ 账号体系、注册登录、跨端同步、订阅支付；④ 消息推送/定时提醒；⑤ 午餐、社交聚餐场景、多城市；⑥ 内容社区、探店、"千人一面"大众推荐；⑦ 交易与资金流。

## 五、品牌时刻候选（≤3 个——趣味性集中投放，不均匀撒）

1. **结果揭晓「今晚就它」**（S6）——产品承诺兑现的一秒：唯一结果＋情绪化推荐语。全部记忆点预算的主战场。
2. **首屏承接「交给我」**（S1/S2）——低能量用户打开的第一秒，视觉要完成"接手"的安全感声明。
3. **回访闭环「它记得」**（S11）——"昨天的 X 怎么样"：记忆层可见化的唯一时刻，被记得＝人格兑现。

其余屏（S3/S4/S5/S7/S8/S9/S10/S12/S13）一律克制：快、清晰、无装饰负担。

## 六、使用环境

> **修订（2026-09-03，拍板后本人补充）**：使用场景不特定在晚餐时段——「虽然产品规划中估计晚餐时段使用率最高，但其实使用场景不特定在某个时间段，最好是界面主题能够跟随季节、时间甚至天气变化」（拍板理由原文）。设计含义：主题须随**时间/季节**自动切换（时段主题系统，见 design-system §1.6）；**天气**项因数据来源与"无位置"红线冲突，登记 G7 未决。

- **时段与光线**：核心时段 17:30–21:30 [假设，U6]（impl §5.1），暗光为默认场景 → **暗色模式为第一公民**；但使用不限于晚间 → 时段主题系统（清晨/午市=亮色片）承接白天使用，暗色片仍是默认与最打磨路径。
- **设备**：手机浏览器直开＋PWA（P-c）；单手持机、拇指热区操作（低能量状态）。
- **网络**：移动 4G/5G 为主 → 首屏 ≤2s 预算下，图片策略趋零（图形走 CSS/SVG）。
- **身体状态**：决策耗竭、瘫坐、注意力残值低 → 信息层级一层一个动作，单屏单焦点。
