## 2. 方案选项与选择

### 选项对比表

| 维度 | 选项 A：最小可行「纯收口器」 | 选项 B：收口器 ＋ 薄味觉记忆（**选定**） | 选项 C：完整「味觉决策引擎」 |
|---|---|---|---|
| 内容 | P1＋P3：打开即 ≤3 道自适应选择题 → 唯一结果 ＋「就吃这个」＋ 最多 2 次「换一个」；无记忆，每次冷启动 | A 的全部 ＋ P2 薄层：3 题冷启动画像、每次决策隐式反馈沉淀（设备本地标识，无账号）、内置 3–4 组经典成对约束（有味↔不油 / 饱↔不撑 / 不贵↔不差）作为生成约束 | B 的全部 ＋ P4 完整自定义约束系统 ＋ 全量味觉记忆模型 ＋ 餐厅数据库接入 ＋ 订阅支付 |
| 验证什么假设 | P1「低成本收口能让用户心甘情愿结束决策」；P3 交互预算（≤30 秒 / ≤5 步）技术可达 | A 的全部 ＋ P2「越用越准」能否驱动回流（使留存可测） | P4 多约束长期价值 ＋ P5 付费闭环 |
| 代价 | ~5 人周；放弃留存验证——无记忆则复用体验衰减，产品退化为一次性工具 | ~6.5 人周（＋缓冲/验证 1.5，总 ≤8 人周 [假设]），8 周窗内可发布 | ≥12 人周 [假设] ＋ 每用户 4–8 周日历时间记忆价值才能显效；**超出 8 周窗口，违背"发布测试"业务目标** |
| 主要风险 | 推荐始终平庸，北极星第 2 周起无从谈起 | 记忆层污染推荐，需可清空/衰减机制 | 在 n=1 证据上对置信度最低的 P4（RICE C=30%）做重资产 |

### 决策：选 B，B 即 §3 的 MVP 范围

理由：

1. **RICE 三轮一致收敛**于"P1 主攻、P3 内化为验收约束、P2 薄层供料"，B 是该结论的直接落地。
2. **不做记忆层则止损信号不可判读**：定稿问题卡 P2 明确"不解决则产品为一次性工具、无留存"——M2/M3 的继续/止损信号都依赖回流数据，选 A 等于花 8 周只验证"能用"不验证"值得做"，P5 风险原样保留。
3. **边际代价可控**：薄记忆层仅 +1.5 人周，总预算仍在 8 人周内。
4. **C 在本窗口是伪选项**：违背 8 周发布测试的业务目标，把最未验证的假设做成重资产，被"统计结论是唯一交付物"（ADR-001/002 共同前提）直接否决；C 中有价值的部分（P4 成对约束）已以窄化形态内嵌进 B。

## 3. MVP 范围

### In（做）

1. **核心收口流**：打开即问 ≤3 道自适应选择题（每题 ≤5 秒可答），输出**唯一结果**（一道菜/品类 ＋ 一句情绪化推荐语）＋「就吃这个」＋ 最多 2 次「换一个」后强制收口
2. **交互预算验收（P3 内化）**：从打开到确认 ≤30 秒 / ≤5 次点击，是硬性验收标准而非优化项；任一步弃答即触发"直接给 1 家"兜底并记录弃答步位
3. **薄味觉记忆（P2 薄层）**：3 题冷启动画像；「就吃这个 / 换一个 / 负反馈」作为隐式反馈写入偏好档案（设备本地标识，无账号体系）；下次决策引用；支持一键清空与偏好衰减，防记忆污染
4. **成对约束窄化形态（P4 内嵌）**：3–4 组固定成对约束作为生成约束，不做用户自定义
5. **一键跳转外卖平台搜索该菜品**（不建餐厅数据库、不做 POI、不做菜品库；深链失效兜底 = 展示菜品名 ＋ 引导手动搜索，沿用 v3 的每日探活机制）
6. **Umami 埋点（对齐 ADR-002）**：会话起止、逐题作答与步数、弃答步位、推荐接受/拒绝/换一、跳转事件与时间戳、链接失效标记、回访曝光与应答
7. **P5 价值探针**：收口后单题 NPS / 付费意愿（抽样触达 ≤1 次/人/周，不打扰主流程）
8. **载体与技术底座（既裁事项）**：H5（微信 webview 内投放），Python 薄 API ＋ SQLite；后端栈 Node/Go 单体 vs FastAPI/Python 按 ADR-001 于 W1 周五以 PoC 数据拍板

### Out（明确不做）

1. 餐厅数据库、菜品数据库、评价体系、任何爬取/对抗刷评（RICE 轮 2 已裁定"数据战争"无胜算）
2. 用户自定义约束系统（P4 完整形态）
3. 账号体系、注册登录、跨端同步、订阅支付
4. 消息推送/定时提醒（ADR-002 裁定放弃，回访靠"次日打开自报 ＋ 群内人肉轻推"）
5. 午餐、社交聚餐场景（问题卡已丢弃）；多城市运营配置（MVP 仅服务负责人所在一线城市）
6. 内容社区、探店、"千人一面"式大众推荐（用户未表达为自身痛点）
7. 交易与资金流（跳转第三方，无 CPS 佣金——资质问题推迟到 M3 收入路径评估时再核）

## 4. 里程碑与验证点

总窗口 8 周；各阶段阈值均为 [假设] 的**方向性判读线**而非统计检验（样本量不支持 95% 置信判别，见表后判读规则）。

| 阶段 | 交付物 | 验证假设 | 继续信号 | 止损/转向信号 |
|---|---|---|---|---|
| **M0**（W1）预验证 | 问题卡/RICE 结论沉淀入 docs；北极星与埋点口径冻结（Wilson 95% CI）；微信群人工 A/B 启动（人工收口 vs 随机转盘，各 ≥30 次 [假设]，承接 v3 Wizard-of-Oz）；后端栈 W1 周五拍板（ADR-001） | P1 在非本人用户身上成立；技术选型在本人产能内 | 人工组「愿再来」≥60% [假设] 或完成决策显著快于自行刷外卖；栈骨架 PoC ≤3 人日端到端走通 | 人工组与随机组无差异 → 冻结构建，回滚问题定义（最便宜的止损点）；PoC 超时 → 降级为规则引擎＋本地菜库的更薄形态 |
| **M1**（W2–W3）狗粮版 | H5 核心收口流 ＋ 薄记忆 v0 ＋ Umami 埋点 ＋ 跳转兜底；本人连续 7 天真实晚餐使用 | P3 交互预算技术可达；LLM 结果可接受 | 7 天中 ≥5 天主动采用；决策时长中位 ≤60 秒；首推接受率 ≥50% [假设] | 不可接受率 >30% [假设] → 收窄生成策略/加本地兜底；步数超预算 → 减题减等待 |
| **M2**（W4–W5）种子版 | 10–30 人 [假设] CBD 种子用户可用版（对齐 ADR 口径 n≈30 会话/周） | P1 跨人群成立 ＋ P2 初值（回流） | ≥40% 用户首周用 ≥2 次；≥25% 次周回流 [假设] | 次周回流 <10% [假设]：归因「结果不合口味」→ 修记忆层；归因「无此场景」→ 回滚问题卡 |
| **M3**（W6–W7）公开测试 | 公测 H5 ＋ 价值探针 ＋ 独立复算的北极星统计报告 | P5 价值可感知（付费意愿/NPS 信号） | 有效回访 ≥40 条；付费意愿 ≥15% 或 NPS ≥20 [假设]；北极星 ≥1.5 [假设] | 回访 <20 条（联动 ADR-002 载体重评）或 NPS <0 且付费意愿 <5% [假设] → 判定「能用但不值得做」，转复盘（发布测试目标本身已完成，不算失败） |
| **M4**（W8）复盘决策 | 全部 [假设] 的实测校准表 ＋ go/pivot/stop 建议 | 下一周期是否值得投入 | 北极星 ≥2.0 且护栏未破 → go（下周期立项） | 北极星 1.0–2.0 → pivot 单条主假设；<1.0 或护栏破 → stop |

> **样本量与判读规则（继承 v3）**：本周期各阶段样本量均不支持 95% 置信的统计判别——n=10 时 60%/40% 阈值仅差 2 人，95% CI 宽约 ±30pp。上表所有阈值均为方向性判读线：验证记录每周随附 n 与 Wilson 95% CI；M2 及以后的对比采用序贯判读（MDE=15pp [假设]），结论标注"定向证据"而非统计证明；任何闸门判定必须同时报告支持它的 n。

## 5. 成功指标

### 北极星指标：周活跃用户人均「心甘情愿收口」次数

定义：分子 = 会话内点击「就吃这个」且次日回访未标记负反馈的决策次数；分母 = 周活跃用户数。投降式拍板（强制收口后接受、弃答兜底接受）不计入分子，单独观测。

- **基线**：上线前 = 0（产品不存在）；现状参照基线 = 目标用户晚间决策 3–4 次/周·人 [假设]，单次耗时 10–22 分钟、以「耗尽投降」收场（n=1 唯一行为证据，占比 ~90% [假设]）
- **目标值**：公测第 4 周（M3 末）≥1.5 次/周·人，复盘闸门（M4）≥2.0 次/周·人 [假设：取可服务频次的约 60%]
- **过程子指标**：决策时长中位 ≤60 秒；会话步数中位 ≤5 步（P3 验收值）

注：产品外行为（跳回平台自刷、真实下单后的体验）在无账号体系下不可观测，以应用内代理或回访自报替代，不做无依据外推。

### 护栏 1（决策质量分）：首推接受率

0 次「换一个」直接收口的占比 ≥50% [假设]；辅助监测 7 日内重复推荐占比 ≤30% [假设]。防止为刷收口次数输出保守重复的平庸答案，把「耗尽投降」换皮成「算法投降」。基线：无历史数据（素材自述盲区），M1 本人使用时首建。

### 护栏 2（负向/打扰率）：收口后单题中「没用 / 反感 / 打扰」占比 ≤10% [假设]

并以「会话步数中位 ≤5 步、决策时长中位 ≤60 秒」为 P3 硬红线（设计验收值，非假设）。防止为完成率重新引入主动打扰——本 MVP 无推送（ADR-002 裁定），依赖"次日打开自报 ＋ 群内轻推"。基线：0（盲区），M2 种子期首建。

### 附：指标–埋点对照

| 指标 | 计算口径 | 依赖埋点事件（Umami） |
|---|---|---|
| 北极星 | 分子定义见上 ÷ 周活跃用户 | 推荐接受、回访应答、会话起止 |
| 决策时长 / 步数 | 打开 →「就吃这个」 | 会话起止、逐题作答、推荐接受 |
| 首推接受率 | 0 次换一直接收口 ÷ 完成会话 | 逐题作答、换一、推荐接受 |
| 重复推荐率 | 7 日推荐去重占比 | 推荐曝光内容标识 |
| 负向/打扰率 | 回访应答中负向占比 | 回访曝光、回访应答 |
| 换一分布 / 弃答步位 | 质量诊断 | 换一、弃答步位 |

## 6. 风险与缓解

| 类别 | 风险 | 缓解 |
|---|---|---|
| **技术·LLM 输出** | 延迟与质量不稳，30 秒预算被推理耗时吃掉；输出不可接受导致连点 2 次「换一」仍不要 | 时段预生成候选池 ＋ 缓存 ＋ 低温度模板化生成 ＋ 本地规则菜库兜底 ＋ 双供应商抽象 [假设：外部 API 成本 <$50/月]；M1 不可接受率 >30% 触发收窄策略 |
| **技术·载体与埋点** | 微信 webview 本地标识清除导致记忆层失效（ADR-002 E-R1）；Umami 双链路税超支（E-R2） | W1 spike 实测 30 天持久性（E-PoC-1）；不持久则降级为"会话内记忆 ＋ 口令恢复"；Umami 超 1 人日即组件级降级自研 ingest，不换载体 |
| **技术·单人产能** | 1 人 ＋ AI 的真实收口速度常败在集成尾巴（ADR-001 判断） | Out 清单守门 ＋ 每项 PoC 时间盒；栈决策 W1 周五死线，逾期取更薄形态 |
| **采用** | 全部规模估算基于 n=1，目标用户可能无此痛或已有 workaround；种子用户来自本人网络，存在礼节性使用偏差；无推送导致回访依从承压 | M0 人工 A/B 以最低成本先行证伪；一切以行为回流而非口头为准；回访靠"次日自报 ＋ 群内轻推"，M3 有效回访 <20 条触发止损并联动载体重评；招募需含非熟人渠道（见未决 #3） |
| **竞争** | 美团/饿了么「帮你选/闭眼点」类功能并非不会上线（美团早有"随便看看"入口，已证伪乐观假设）；通用 AI 助手可直接问"吃什么" | 差异化押注交互预算极限（≤5 步）＋ 个人味觉记忆 ＋ 成对约束，不拼餐厅数据；本周期为验证期不做正面对抗。**监测机制（继承 v3）**：每两周固定检索巨头版本更新与行业媒体；黄色预警 = 任一巨头上线同类功能（记录并加测留存）；红色触发 = 黄色预警成立且北极星连续两周下滑，或首推接受率下滑 ≥15pp [假设阈值] → 冻结后续投入，止步于验证报告 |
| **合规** | 无支付、无账号，整体低风险；残留三项：偏好数据经 LLM API 传输（PIPL）、webview 标识的个人信息定性、饮食健康边界 | 偏好数据脱敏聚合后传输 ＋ 隐私声明；H5 载体天然规避小程序 openid 身份口径（ADR-002 裁定依据）；禁止输出健康/减脂类建议，加"特殊饮食需求请遵医嘱"免责说明；数据最小化——只存匿名标识 ＋ 决策行为。CPS/联盟资质本期不涉及，M3 评估收入路径时再核 |
