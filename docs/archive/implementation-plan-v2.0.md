## 1. 架构总览

### 1.1 组件与数据流（ADR-002 候选 E 落地形态）

**静态 H5 + 薄 API：单仓、一份静态产物 + 一个 API 镜像 + 单库文件。** Docker Compose 4–5 容器（视 Umami 分支），需要人运维关注的活动部件 3–4 个：api + cron（+ Umami + 其自带 PG，若保留）；caddy 为无状态边缘（TLS、静态资源、静态兜底页、反代），配置冻结、故障即重启，不构成运维面。

- **静态壳（Vite 构建，caddy 直接托管，无 SSR）**：隐私弹窗（B-07）→ **双路径分流（产品 v3 §3 In-1）**——主路径"直接给答案"（0–1 题快选即出 ≤3 家）＋ 可选深挖路径（5–7 步单选题，F-01，P2 最小形态载体）＋ 全程可见"随便吧"出口（F-02）＋ **任一步弃答即触发"直给 1 家"兜底并记录弃答步位**（产品 v3）→ ≤3 家候选呈现（F-06）→ 深链跳转/兜底页（F-07/F-08）→ 免责声明（F-15）→（P3）次日自报回访单问句（F-10，H5 口径，**抽样触发：每人每周 ≤1 次**，服务端判定）。**API 与 UI 第一天强制分层**（静态壳只调 JSON API）：ADR-002 翻案条件若成立可加小程序薄壳，不动 API。
- **api 容器（薄自研 API，栈 = ADR-003 待拍板）**：会话生命周期、双路径策略下发、埋点 ingest、回访上报、健康检查、Admin 面；零页面逻辑。若选 Python（B′）：FastAPI + uvicorn async worker 数论证并发（≤10 轻松）；若选 TS：Node 单进程事件循环论证——栈敏感论证随 ADR-003 结论落地面写入。
- **Umami + umami-db 容器（条件组件，E-R2 分支）**：**仅作原始事件接收**——api ingest 入 SQLite 后服务端转发 send-events（端上零改动、双写一致）；**口径单一事实源在自家 SQLite 日表侧，Umami 只提供流量面板与原始事件副本**。T0.3 PoC-2 预验（导出字段零丢失 + 实际集成税 ≤1 人日），任一不达 → **组件级降级为自研 ingest**（回归 ADR-001 候选 A/B′ 自研埋点路径，不换载体），并回写 ADR-002 D6 重评记录留痕（架-1/架-4）。
- **cron 容器（Alpine + sqlite3/psql + 脚本，无长驻进程）**：① 深链探活（15:30 启动、16:30 前完成，核心时段 17:00–21:00 前，F-09，**含 1–2 个对照 URL**，§2.4）；② 备份（03:00，双库条件分支，§2.5）；③ 日表聚合（02:00，F-12）；④ 高德配额对账（23:59，与 §4.1 实时累计对账）。cron 直写 SQLite（同机 WAL 多进程读写安全，仅 INSERT probe/audit/daily_metrics）。
- **caddy 容器**：自动 TLS；静态资源版本目录托管与原子切换；**`/offline` 静态兜底页直接服务（零 API 依赖：品类引导 + 平台入口 + 手动搜索指引——api 全死时用户不白屏，运-4）**；api/Umami 反代；访问日志 7 天轮转（§4.2）。

**数据流（一次决策会话，双路径）**：
1. 打开 → caddy 出静态壳 → `POST /api/session/start`（localStorage 匿名 UUID，F-14）→ 三层限流检查（§4.1）→ 建会话、按序贯策略定 variant（F-13）、返回当日深链健康状态（F-09）、`path_default`（默认直给）、`visit_probe`（回访抽样判定）。
2. **直给主路径**：0–1 题快选 → `quiz-complete`（0 题时携带 skip 标记）→ 下发映射 + 深链模板 → 端上高德拉取 → ≤3 家呈现；**深挖路径**：逐题 `answer`（携带 `path`）→ 末题 `quiz-complete` → 同上；**弃答兜底**：任一路径中途弃答 → 上下文足够则"直给 1 家"，否则兜底页 → `abandon` 事件（含步位与 path）。
3. **端上高德 JS SDK（H4 核心）**：位置 → 周边搜索 → 品类过滤全在浏览器完成，web key + 域名白名单；服务端零 POI 落盘、零代理转发（NFR 2.4）。**定位/拉取失败降级链（架-5/运-1）**：geolocation 失败或拒权 → 重试 1 次 → **手动商圈选择**（config 下发商圈清单）→ 仍失败 → `/offline` 兜底页；每一级打 `amap_call`/`fetch_fail` 事件（含失败原因 payload，§2.1）。
4. 接受/拒绝/随便吧/放弃 → `decision`（**携带 `amap_call_count`**，服务端实时累计当日配额消耗，§4.1）→ 深链跳转（无佣金，H5）或兜底"店名+手动搜索"（F-08）。
5. 会话埋点批量上报（**11 类**，F-11 v3 扩充；会话结束 1 次批量 POST）→ ingest 入 SQLite（权威）+ 转发 Umami（若保留）。
6. 次日（P3，`visit_probe=1`）：回访曝光/应答事件（F-10）。

**统计出数流**：cron 02:00 聚合日表（含直给路径占比、fallback 会话标记、amap 日调用数）→ 周报 SQL 直查 + 全量 CSV 导出（B-05）→ Wilson 95% CI 双实现交叉验证（胜出栈生产实现 + Python pandas 离线复算，ADR A-3；两实现独立编写、不共享统计库）。

### 1.2 关键接口契约概要

错误契约统一 `{error:{code,message}}`；限流命中返回 429；兜底模式（探活全红且对照绿）返回 503 + `fallback_mode:true`，前端直接走兜底页。

| 接口 | 方法 | 请求要点 | 响应要点 | 回链 |
|---|---|---|---|---|
| `/api/session/start` | POST | `anon_id`(客户端 UUID) | `session_id`、`variant`、`config_version`、`path_default`、`visit_probe`、`link_status{date,overall,fallback_mode}`；>10 会话/天/标识或 >200 会话/天/IP → 429；全局熔断态 → `fallback_mode:true` | F-14、F-13、F-09、B-09 |
| `/api/session/{id}/answer` | POST | `step`、`choice_id`、`path`(direct/deep)、`client_ts` | 204；服务端 `server_ts` 为权威时钟 | F-01、B-04 |
| `/api/session/{id}/quiz-complete` | POST | 全题答案集（直给可为空+skip）、`path`、`amap_call_count` | `mapping`、`deeplink_templates`、`match_note:"品类级"`、`location_fallback_hint`（定位已失败时提示手动商圈）；熔断态停发并返回 `fallback_mode:true` | F-04、F-05 |
| `/api/session/{id}/decision` | POST | `action: accept_first\|accept_other\|reject_all\|random_exit`、`source: path_flow\|abandon_fallback`、`candidate_name`、`amap_call_count` | 204；`random_exit` 不计北极星分子；弃答兜底接受以 `source` 区分 | F-02、F-06 |
| `/api/session/{id}/jump` | POST | `candidate_name`、`platform` | 204；北极星"≤3 分钟"的服务端时间锚点 | F-07、F-11 |
| `/api/events/batch` | POST | ≤50 条/批，`client_event_id` 幂等去重 | 204；**11 类**事件枚举校验；当日全局写入护栏超限 → 429 + P1（§4.1） | F-11 |
| `/api/link-status` | GET | — | 当日探活结论（含对照 URL 状态） | F-09 |
| `/api/visit-report` | POST | `anon_id`、`answer: 满意\|将就\|后悔` | 204（回访曝光/应答两类事件） | F-10、F-11 |
| `/api/health` | GET | 无鉴权 | `db_writable`、`disk_pct`、`version`、`quota_breaker`、`umami_status`（若保留） | B-03 |
| `/api/admin/*` | — | Bearer `ADMIN_TOKEN`，路由不经 caddy 暴露，仅 SSH 隧道直达 api 容器端口 | 导出 CSV/JSON、配置与实验版本切换、审计查询、日表读取、按 anon_id 数据清除（§4.2） | B-02、B-05、B-06 |

### 1.3 策略配置（M2 迭代的载体）

`config` 表（key–JSON）：题目/选项文案版本、**路径分流规则（直给默认快选项集）**、约束→品类映射表、深链模板、**手动商圈清单（定位降级用）**、**回访抽样规则（每人每周 ≤1 次）**、实验开关与分组策略、全局兜底开关。修改经 Admin API → 写 audit_log → 进程内缓存失效，**生效 ≤1 分钟**（B-06）。M2 的"通用选择题版 vs 约束映射版"切换、约束选项迭代、深链模板更换全部走此通道，不动代码。

**config 写入三道闸（v1.1 保留）——任何 config 写入必须全部通过：**
1. **JSON Schema 校验**：每个 config key 配 schema，校验失败拒绝写入；
2. **写后即时冒烟**：解析关键字段各取 1 条模拟下发到测试会话，失败进入第 3 道；
3. **失败自动回滚**：恢复 audit_log 中 `before` 值 → P2 告警 → 生效值始终是上一次通过全闸的版本。
三道闸验收写入 T1.4；全程 <2 秒，不影响"≤1 分钟生效"。

## 2. 数据模型与存储设计

### 2.1 核心实体（SQLite WAL 单文件 `app.db`）

| 表 | 关键列 | 说明与回链 |
|---|---|---|
| `sessions` | `id` PK、`anon_id`、`path`(direct/deep)、`status`(started→answering→presented→accepted/rejected/bypassed/random_exit/abandoned 状态机)、`started_at/ended_at`(Unix 秒,服务端)、`last_step`、`abandon_step`、`variant`、`link_valid_flag`、`fallback_mode`、`visit_probe` | `link_valid_flag` 承载链接失效剔除口径（F-09/F-12）；**`fallback_mode` 承载熔断/兜底期剔除口径（运-3，§2.2）**；`path`/`abandon_step` 支撑主路径假设 ⑤′ 与弃答分析（产品 v3 §5）；无身份字段（H3）；`anon_id` 支持级联清除（§4.2） |
| `events` | `id` 自增、`client_event_id` **UNIQUE**（幂等）、`session_id` FK、`anon_id`、`type`(**11 类**枚举 CHECK)、`step`、`payload` JSON、`client_ts`、`server_ts` NOT NULL | **11 类 = 会话开始（含 path 标识）/ 会话结束 / 逐题作答（含步数）/ 弃答（含步位+path）/ 随便吧 / 逐推荐接受拒绝 / 深链跳转+时间戳 / 链接失效·兜底模式标记 / 端上高德调用计数 amap_call（含 fetch_fail 失败原因）/ 回访曝光 / 回访应答**（F-11 v3 扩充，架-2/运-1）；时长口径一律 `server_ts`（B-04）；**直给路径答题段时长锚 = 会话开始 → quiz-complete 的 server_ts（呈现触发点，偏差 <1 秒）**；payload 中 `candidate_name` 为准标识符（L1 管理、级联清除，D-9） |
| `experiment_assignment` | `anon_id`+`period_key` UNIQUE、`variant`、`strategy`(sequential_week/first_exposure) | 序贯对照（F-13、S7）；标识丢失退化判据见 §4.1（D-15） |
| `probe_results` | `check_date`+`link_key`、`platform`、`status`(ok/fail)、`control_status` | 每日探活结果（F-09）；**`control_status` = 对照 URL 状态（运-2）：对照绿+目标全红才自动降级，对照红 = 探活通道自身故障（P1 不降级）** |
| `config` | `key` PK、`value` JSON、`updated_at/by` | §1.3（三道闸） |
| `audit_log` | `actor`、`action`、`target`、`before/after` JSON、`at` | B-02 全量留痕（§4.3）；**anon 数据清除执行后，`target` 中该 anon_id 同步替换为盐化哈希（安-2，可审计不可逆）** |
| `daily_metrics` | `date` PK、`metrics` JSON | F-12 日表：北极星分子分母（**剔除失效与 fallback 会话**）、答题段时长分布（分路径）、**直给路径占比（产品 v3 §5 过程指标）**、放弃/旁路（含弃答步位分布）、首选项接受率、两级漏斗、**fallback 会话数与占比、amap 日调用数**、当日全新 anon_id 占比 |

### 2.2 一致性要求

- **持久性**：`PRAGMA synchronous=FULL` + WAL——写入频率极低（§2.3），换进程崩溃零丢失（NFR 2.3 RPO）。
- **幂等**：埋点以 `client_event_id` 唯一约束去重。
- **并发**：`busy_timeout=5000ms`、`foreign_keys=ON`；单写者串行（app 主写 + cron 夜间写，时间错开）。
- **权威时钟**：闸门判读一律 `server_ts`；`client_ts` 仅存档比对。
- **口径单一事实源**：全部指标计算 SQL 收敛在 `daily_metrics` 生成器一处，周报与导出只读日表。**剔除口径（运-3，与 F-09/F-12 对齐）：①"随便吧"不计北极星分子；②链接失效会话（`link_valid_flag`）不入 M1 达标口径；③配额熔断期/全局兜底期会话（`fallback_mode`）不入北极星与接受率分母——熔断是本方案新增的常态路径，不标记即污染 M1 判读。日表同时记录 fallback 会话占比，**日占比 >20% [假设] → P1**（口径污染面监控）**。

### 2.3 容量与性能核算（规则 2：全部标 [假设]；v3 口径）

| 项 | 设计值 | 依据 |
|---|---|---|
| 会话量 | 峰值 ~30 会话/周（M1 末起）；**全周期 120–150 会话**（v3 口径，修正 v1.1 的"8 周 240"高估——W1–W4 构建/爬坡期无 30/周流量） | ADR-002 背景数字（NFR 2.2 v3）[假设：招募达标] |
| 事件量 | 直给会话 ~8–12 事件 × 深挖 ~15–25 事件，混合 **≤3,500 条**；单条 1–2KB → 库文件 <50MB；Umami 副本同量级 [假设] | NFR 2.2 v3（<1 万条/<100MB）内，余量 >2× |
| 写吞吐 | 稳态 <0.05 QPS；晚餐窗峰值批量写 <2 QPS [假设：并发 ≤10 中同时在线 ~3–5 × 会话末批量上报] | SQLite WAL 单写者能力余量 >100× |
| 读吞吐 | **QPS ≤1（v3 设计值）**；实际预计 <5 QPS（静态资源走 caddy 直接服务，不打 api） | NFR 2.1 v3 |
| 并发 | **≤10 并发会话（v3）**；栈敏感：TS 侧 = Node 单进程事件循环论证；Python 侧 = uvicorn worker 数论证——随 ADR-003 结论落 ADR-003 落地面 | NFR 2.1 v3 |
| 探活规模 | ~50 链接 + 2 对照 URL × 1 轮/日，15:30–16:30 完成，单轮 <10 分钟 [假设] | §2.4 |
| 延迟预算 | **呈现 P95 ≤3s / P99 ≤8s（v3 验收口径）**；设计内控预算 P95 ≤2s（定位 <500ms + 高德拉取 1.2s + 映射 <100ms + 渲染 <200ms）[假设：4G 弱网]；单题切换 P99 ≤300ms（纯本地）；首屏 ≤2s（静态 + gzip <300KB [假设]）；api P99 <200ms（不触第三方） | NFR 2.1 v3 |
| 增长假设 | 本设计仅在 ≤500 会话/周内有效 [假设]；超出触发存储/架构重评（ADR-001 重评条件 5） | 绿地原型 |

### 2.4 探活清单（合规边界显式声明 + 对照面）

服务端不存 POI 数据库（H4），探活对象 = **人工标注的 `{店名字符串, 平台, 深链模板变量}` 配置文件**（50 条，源自 P0-3 标注），不含经纬度/品类/评分等 POI 元数据、不来自 API 抓取缓存。此边界解释在高德条款核对中一并确认（未决 U2/U6）；若被认定受限 → 店名哈希化或降级抽样探活（D-9）。

**探活对照面（运-2）**：清单固定加入 **1–2 个稳定第三方对照 URL**（如 `example.com`、任一大站 favicon）。判定规则：**对照绿 + 目标全红 → 自动切全局兜底 + P1**（平台侧失效）；**对照也红 → 探活通道自身故障（VPS 出口网络/脚本 bug）→ P1 告警但不自动降级**，人工 5 分钟定性后决策——防止把探测基础设施故障误判为平台封禁、白白烧掉不可重放的会话。

### 2.5 备份与恢复（B-01、ADR A-2；双库条件分支，架-4）

- **每日 03:00（主分支：Umami 保留）**：① `sqlite3 app.db ".backup /backup/app-YYYYMMDD.db"`（在线一致性快照，**严禁直接复制文件**，ADR A-2）；② **Umami 自带 PG：`pg_dump` 至 `/backup/umami-YYYYMMDD.sql`**（埋点原始副本，与 app.db 同日配对，**缺任一半份即视为该日备份失败 → P1**）。两份产物 `age` 加密 → rsync 至本人控制介质（外置磁盘 + 第二块移动硬盘；不使用公有云对象存储，与 §4.2"数据不出境"统一）。
- **降级分支（E-R2 触发自研 ingest）**：单库 `app.db` 备份，恢复 v1.1 口径。
- **保留**：日备 9 周 + 周备 12 个月（与数据留存 ≥12 个月对齐，NFR 2.5）。
- **恢复演练**：M1 上线前脚本化 ≥2 次（B-01），**主分支两次演练必须覆盖双库**（app.db 恢复 + PG 导入回灌 + 埋点对账抽核 1 日）；目标 RTO ≤4h（NFR 2.3 v3，实操目标 30 分钟内）。脚本入库 `scripts/restore-drill.sh`。
- **RPO**：24 小时（日备粒度）；events 写入即持久化，宿主机级故障最多丢 1 天。

### 3.1 环境

| dev | 本人本机 compose | 日常开发、冒烟 | 独立 `app.dev.db` + 合成数据 |

### 3.2 发布策略（目标：合并 → 上线 ≤30 分钟，NFR 2.5；E 形态双轨发布）

trunk-based 短分支；api 镜像 tag = git short sha；静态产物按版本目录管理；发布前冒烟 100% 执行（B-08）。E 形态结构性优势：**前端与后端可独立发布、独立回滚**。

**发布序列（执行人 = 本人，全程 ≤30 分钟）：**

| 步 | 动作 | 耗时 |
|---|---|---|
| 1 | merge → `git tag vN` | 2 分钟 |
| 2 | 本地 `docker build`（api）+ `pnpm build`（静态）+ 冒烟脚本（compose 起 → 端到端：直给路径 → 深挖路径 → 收 3 家 → 埋点行数校验 → 随便吧事件校验 → **定位拒绝场景走手动商圈降级** → 探活表可写） | 10 分钟 |
| 3 | api 镜像推 registry；静态产物 rsync 至服务器 `/static/vN/` | 3 分钟 |
| 4 | `docker compose pull && up -d`（仅替换 api；cron/caddy/umami 不动）+ symlink `/static/current → vN` 原子切换 + `/api/health` 绿 | 3 分钟 |
| 5 | 线上手工冒烟（双路径各 1 次 + 定位拒绝 1 次，真实手机 4G [假设：模拟弱网]） | 7 分钟 |
| 6 | audit_log 写发布记录（tag/变更点/回滚点） | 2 分钟 |

**前端独立回滚 = symlink 切回上一版本目录，<1 分钟**（不动 api、不发版）。

**M2 周节奏**：每周二 14:00–16:30 固定发布窗（避开核心时段 17:00–21:00；该窗口内禁止变更，除非 P1 故障）。

### 3.3 数据迁移（绿地 + 前向 only）

- 首次部署 = schema init（`migrations/0001.sql`）；无存量迁移。
- 后续变更 **expand-only**：只加表/加可空列；禁止 rename/drop/改类型（旧镜像可跑新 schema，回滚不动库）。8–9 周内预计 schema 变更 ≤3 次 [假设：M2 迭代以 config 为主]。
- 迁移脚本顺序编号入库，发布序列步骤 2 对生产库副本预演执行。
- 第 3 次以上 schema 变更 → 引入正式迁移框架（技术债 D-10）。

### 3.4 回滚动作序列（目标 ≤10 分钟，NFR 2.5）

**触发条件**：线上冒烟失败 / P1 告警（§5）/ 数据异常写入。执行人 = 本人。

| 步 | 动作 | 耗时 |
|---|---|---|
| 1 | 决策回滚（§5 runbook 判定层级：先 restart、后 rollback、最后 restore） | ≤2 分钟 |
| 2 | api：`IMAGE_TAG=<上一稳定 tag> compose up -d`；前端：symlink 切回（schema 前向兼容，库不动） | 3 分钟 |
| 3 | `/api/health` 绿 + 冒烟 | 3 分钟 |
| 4 | audit_log 记回滚 + 通知（若影响用户，次日群内说明） | 2 分钟 |

**数据损坏路径（RTO 实操 ≤30 分钟，承诺 ≤4h）**：`compose down` → 最近备份 `integrity_check`（app.db）/ `pg_restore --list`（Umami）→ 替换卷内库 → `up -d` → 冒烟。

**M2 双版本切换（≤1 分钟，B-06）**：Admin API 改 `config.experiment.active_variant` → 过三道闸 → 缓存失效 → 新会话按新 variant 分组；不重启不发版，写 audit_log。

## 4. 安全设计

### 4.1 认证与授权

- **用户侧**：无账号（F-14/H8）。匿名标识 = localStorage UUID v4；"认证"不存在，"识别"仅到匿名标识粒度。
- **匿名标识持久性风险（E-R1/D-15）**：微信 webview 可能清 localStorage → anon_id 静默重生 → 序贯分组退化。对策：① T0.3 实测（安卓/iOS 各 1 台 × 3 天常规 adverse 操作，30 天窗口逻辑外推）；② 预写退化判据：实测清除 → `first_exposure` 按周期分组、日表标注"标识不持久期"、实验结论降档组间对照；③ §5.1 全新 anon_id 占比告警兜底。
- **三层限流（B-09；安-1）**：
  1. **anon_id 维度**：>10 会话/天/标识 → 429 [阈值假设]；
  2. **IP 维度**：>200 会话/天/IP → 429 [阈值假设]——针对"链接扩散 → 新访客即新 ID"的刷量脚本；实现 = caddy 或 api 中间件内存计数，**IP 经盐化哈希后仅作内存 key，不落库、重启即清零**（与 §4.2 运维日志 L1 行口径呼应）；
  3. **全局写入护栏**：当日 events 总写入 >2,000 条（≈8× 预期日峰 250 [假设]）→ ingest 返回 429 + **P1 告警**——保护的是自己的磁盘（2C2G VPS），不只是高德配额。
  三层均写入 T1.7 验收（含 1 次模拟刷量演练）。
- **全局熔断（运-1 修订：实时累计替代会话末估算）**：端上高德调用数由 `quiz-complete`/`decision` 请求**实时携带**（`amap_call_count`），服务端当日累计——不再依赖会话结束才批量上报的埋点估算（天然滞后一个会话，晚餐窗 20 个会话足以在熔断触发前烧穿 <100 次/日量级配额）；`amap_call` 事件留作对账。**当日累计 ≥配额 80% → P2；≥95% → 熔断态：quiz-complete 停发 mapping、session/start 返回 `fallback_mode:true`，前端直走兜底页（零外部 API 消耗），直至次日窗口**。配额数字未核实（U2）前，**阈值按保守下限 100 次/日执行** [假设]。熔断进入/退出写 audit_log + P1。
- **Admin 面**：`ADMIN_TOKEN`（64 字符随机，环境变量注入）；路由不经 caddy 暴露，仅 SSH 隧道直达 api 容器；所有调用写 audit_log（单人最小充分方案，D-3）。

### 4.2 数据分级与合规要点

| 级别 | 内容 | 处置 |
|---|---|---|
| L0 公开 | 题目/选项文案、静态资源、免责声明 | 无限制 |
| L1 匿名行为（含准标识符） | sessions/events/experiment/probe/daily_metrics（含店名等准标识符——不再声称"PII 无"；组合理论上可间接识别，按 L1 严管） | TLS 传输；明文 HTTP = 0（NFR 2.4）；导出走 Admin 鉴权；支持按 anon_id 级联清除 |
| **L1 运维日志（安-3 新增）** | **caddy 访问日志（含 IP/UA/Timestamp）** | **7 天轮转（caddy 内置 rotation）；不入备份、不异机留存；IP 不入任何持久化业务表（限流用内存哈希 key）** |
| L2 运维敏感 | audit_log、config、备份文件、ADMIN_TOKEN | 备份加密（age）+ 本人控制介质；token 仅环境变量 |
| 位置数据 | 仅端上当次筛选计算，不落库不传服务端（NFR 2.4） | — |

**用户数据清除（安-2 修订：承诺可操作）**：Admin 面 `POST /api/admin/anon-data/delete`（`anon_id` 参数）级联删除 sessions/events/experiment_assignment 全量行（`ON DELETE CASCADE`）；**用户触达路径闭环**：隐私弹窗与页脚常驻"我的数据"入口——**展示该浏览器当前 anon_id + 一键复制按钮**（用户拿着它到微信群说"删这个"），文案"清除浏览器标识后联系我们即删除服务端记录"（M1 微信群人肉通道）；**清除执行后 audit_log 中该 anon_id 同步替换为盐化哈希**（可审计、不可逆，堵住"审计表永久保留已删用户标识"的漏洞）。T1.8 实现、T1.9 前演练 1 次。

合规要件落地：隐私弹窗首访 100% 覆盖（B-07，含数据用途/匿名/**删除权行使方式**/**运维日志用途一句**——个保法告知同意要件，H6）；免责声明常驻页脚（F-15）；无佣金深链期间佣金链接数 = 0（H5）；数据不出境（NFR 2.4）。**法务确认（U9，安-4 修订）**：W1 内落实具体渠道（线上法律咨询服务 [假设：¥300–800 一次性行情] 或熟人律师）；**若 W1 末仍不可得 → 降级为"AI 起草 + 个保法/工信部公开合规指引逐条自查留档"**，不再作为上线硬闸的悬空资源——降级决定本身写 audit_log。

### 4.3 审计日志（B-02）

记录：数据源切换、深链全局兜底开关、**探活对照判定**、配额熔断进入/退出、三层限流护栏触发、实验版本/分组策略变更、config 任何变更（含三道闸回滚）、数据导出、anon 数据清除（清除后标识哈希化）、发布/回滚。保留 ≥12 个月。cron 自动动作 actor = `system:cron`，人工动作 actor = `owner`。

## 5. 可观测性

### 5.1 关键指标与告警阈值（NFR v3 口径）

| 指标 | 采集 | 阈值 → 动作 | 回链 |
|---|---|---|---|
| 服务可用性 | 外部拨测 5 分钟/次（X7）+ caddy active healthcheck | 拨测失败 → webhook（触达 ≤5 分钟，B-03）；**核心时段 17:00–21:00 内 = P1** | NFR 2.3 v3 |

### 5.2 半夜/离线报警第一响应 runbook（执行人 = 本人）

1. **定性（1 分钟）**：告警标题映射类别——不可用 / 备份失败 / 探活全红 / 磁盘 / 数据回流 / 配额熔断 / 写入护栏。
2. **非核心时段且非数据类 → 降级**：次日 09:00 处理（非决策时段 ≥99.0%，NFR 2.3 v3）。唯一例外：备份失败当下手动跑一次验证可读（数据资产不过夜裸奔）。
3. **核心时段不可用（P1）**：`compose ps` 定位 → `restart api`（3 分钟）→ 不恢复按 §3.4 回滚（10 分钟）→ 疑库损坏走数据恢复（30 分钟）。**api 死不等于服务死：静态壳自动引导 `/offline` 兜底页，用户侧为降级而非中断**。全程超时即接受当次损失并复盘——会话不可重放，止损优先于根因。
4. **探活全红**：**先看对照 URL**——对照红 = 探活通道自身故障，修探活不降级；对照绿 + 目标全红 = 平台侧失效 → Admin 切全局兜底（1 分钟生效）+ 审计；当晚会话自动带失效标，统计按 §2.2 口径剔除。
5. **配额熔断（P1）**：确认由真实消耗触发（查实时累计明细）→ 保持兜底至次日；次日排查来源（链接扩散？用全新 anon_id 占比 + IP 维度限流命中记录定位）。估算 bug → 手动解除 + 修口径。
6. **写入护栏（P1）**：IP/全局护栏触发 = 刷量或埋点 bug——查 IP 命中分布；真刷量 → 收紧 IP 阈值 + 必要时临时封禁该哈希；bug → 修复 + 手动解除。
7. **数据回流断（P1）**：查 `/api/health` 与 api 日志；埋点入库失败 → restart；持续失败接受缺口并在日表标注（D-14）。
8. **收尾**：任何动作写 audit_log；P1 次日补一页复盘笔记。
