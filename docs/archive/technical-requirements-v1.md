## 五、复杂度风险点（最影响架构的三个不确定点）

**R1. 供给侧"外卖可得性"数据路径可能不存在（影响：F-03 / F-05 / 整个数据层）**
"可配送至用户位置"是候选池的硬准入条件（§3 In-2），但高德 POI 是到店轴数据、无外卖可得性字段；外卖平台的店铺列表/配送范围数据无公开 API，联盟 API 面向推客且个人主体准入未决（§7 #2）。若两条路都走不通，"外卖可得性优先"在数据层面不可实现，首选项接受率 ≥50% 的验收（§4 M1）在数据结构层面不可达（§6 已明确警示）。它还与 H4（端上实时拉取、服务端不缓存）耦合：外卖平台数据的获取方式若必须服务端代理，将与高德存储条款的合规路径直接冲突。P0-3 spike（50 家人工标注）只能裁定"该不该换源"，裁定不了"外卖数据拿不拿得到"——后者是第 1 周内必须并行验证的最大架构不确定点。

**R2. 深链静默失效 × 探活代表性 × 指标口径的三方耦合（影响：F-09 / F-12 / §5 全部出口指标）**
深链封禁可任意时点静默发生（§6 技术·匹配），因此探活-兜底-打标-剔除构成一个横跨数据采集、统计口径与前端呈现的闭环。不确定点在于探活的"代表性"：每日心跳通过 ≠ 真实用户跳转成功（深链可能因参数、地域、端上版本差异而部分失效）。探活方案若设计不当，会同时污染北极星（跳转事件）、首选项接受率（剔除口径）与 CPS 漏斗（§5）——即产品结论本身失真，且这种失真在 n≈30 会话/周的样本量下无法靠统计检出。探活策略（探什么、按什么粒度探、失效如何判定）需要在 M1 构建前定稿，返工成本高。

**R3. 载体未决（小程序 vs H5）牵动三个子系统的形态（影响：F-10 / F-11 / F-13 / 迭代节奏 / H3）**
1 天 spike（§7 #4）要同时回答四类问题：微信审核周期与类目要求（M2 需要每周迭代，审核可能锁死节奏）；深链能力差异（与 R2 叠加）；回访触达（小程序订阅消息需授权点位设计且涉及 openid 存储——与 H3"不存任何身份信息"存在张力，需合规口径；H5 无推送能力，回访退化为"次日打开自报"，P3 依从率的数据口径完全不同，直接影响 M3 的 ≥40 条目标可达性）；埋点能力差异。载体结论还决定 F-13 实验切换与 F-01 流程的实现载体。该决策在第 1 周必须闭合，且三个子系统（触达、埋点、发布链路）的架构形态都挂在它上面——是单点决策撬动最大架构面的不确定点。
