# 【吃什么】产品规划文档

> 角色：产品负责人 ｜ 日期：2026-09-02（v3 修订版）
> 依据：问题定义卡（P1 决策收口 / P2 多约束匹配 / P3 体验沉淀）+ RICE 排序会话结论 + 多角色评审会话两轮意见（第一轮 #1–#9 已吸收进 v2；第二轮 #1–#11 本版并入，其中 #8 驳回）
> 约束前提：1 人 + AI agent，验证窗口 1–2 个月；全部证据为 n=1 自访 [假设级]，唯一行为级证据为 18:12–18:58 在家点外卖的决策亲历记录
> 本文档所有目标数字均给出基线并标注 [假设]；约束补齐后（尤其业务目标从"验证问题"变为"变现/增长"）需整体重切
> Reach 悲观链路（评审二 #4）：Reach 70% [假设] 存在最悲观情景——若每周决策总损失仅 ~20 分钟（时长 × 频次 × 托付率连乘的下界），P1 的 RICE 分值将显著低于基准 4,875；M0 行为数据校准前，Reach 相关结论均为低置信
> v2 修订要点：新增 M0 开工前置闸门（业务目标 / 招募 / 供给侧数据 spike）；候选池改为"外卖可得性优先"；全部验收指标重定义为应用内可观测口径并附埋点对照；各阶段阈值标注样本量与判读级别；新增深链每日探活、竞争监测触发条件、最小经济性指标、回访触达方案
> v3 修订要点：交互改双路径（"直接给答案"主路径 + 选择题深挖，评审二 #9）；回访改抽样触发（评审二 #10）；载体裁决升格为开工前置 P0-4 并新增"载体不可用"风险行（评审二 #6）；满意度自报口径锁死与降级机制（评审二 #3）；竞争行修正"平台不会跟进"的已被证伪假设并加竞品实测复核（评审二 #2）；M2 序贯判读细化，低置信结论不单独裁决大投入（评审二 #7）；M3 新增收入路径候选集与 side project / 创业两套 go/no-go 判据（评审二 #1/#2）；总窗口加 0.5–1 周缓冲（评审二 #11）

## 1. 新闻发布会标题

**「90 秒，直接给你答案；最多 3 分钟，把"今晚吃什么"收口——别再刷 20 分钟，最后点一个"随便"。」**

> 口径注（评审一 #4、二 #9）：**90 秒 = 直给路径**（打开→出 ≤3 家推荐）或**选择题答题段**（5–7 步作答）的目标时长，作为独立子指标在 §5 跟踪；**≤3 分钟 = 全流程**（打开→"就这家"→跳转点单）承诺，与 §5 北极星同口径。两个数字各管一段，不混用。

## 2. 方案选项与选择

### 选项对比表

| | 选项 A：冒烟测试先行（零工程） | 选项 B：最小可行方案（双路径收口 MVP） | 选项 C：完整方案（三问题闭环产品） |
|---|---|---|---|
| **一句话内容** | 人肉 + AI 混合充当"收口员"：饭点在微信里以直给版 + 选择题版双话术替 8–15 人次收口，全程无产品 | 双路径收口 MVP：小程序/可点击原型，主路径"直接给答案"（0–1 题快选即出 ≤3 家，评审二 #9）+ 可选深挖路径 5–7 步选择题（内嵌 P2 最小形态：约束→筛选映射）+ **外卖可得性优先的候选池（高德 POI 或外卖平台店铺列表，由 P0-3 数据 spike 裁定，评审一 #5）** + 每次仅呈现 ≤3 家 + 深链/CPS 跳转点单；P3 留抽样回访探针 | 在 B 之上做多约束匹配引擎（口味画像 + 矛盾约束求解）+ 个人餐历沉淀（回访闭环、跨端记忆、个性化排序），P1/P2/P3 三问题闭环 |
| **验证的核心假设** | ① 目标用户愿意把晚餐决策交给工具收口（直给或选择题任一形态；Reach 前提自报 60–80% [假设] 的行为级检验）② 直给/选择题能否命中"多约束"（每家"差一点点"是否消失） | A 的全部 + ③ 产品形态下从"问"到"点单"的转化真实存在（不是给人情面子）④ 决策时长可压至 ≤3 分钟且结果满意度不降；⑤' 直给/选择题两路径的真实偏好（主路径假设的行为级检验，评审二 #9） | ⑤ 个性化记忆经 20+ 餐积累后显著提升决策质量 ⑥ 三问题闭环产生 1+1+1>3 的留存 |
| **代价** | ~1 人周；无工程；但人力随用户数线性增长，无法规模化；验证不到真实产品形态下的使用意愿 | ~6.5–7 人周（构建 2.5–3 + 实测 1–1.5 + P2 内嵌增量 ~2 [RICE 会话口径] + 回访触达链路 0.5–1 [评审一 #8]）；需外卖可得数据源（P0-3 裁定）、载体结论（P0-4 裁定）与小程序审核 | ~11+ 人周，超出 1–2 月窗口；P3 的真约束是日历时间（每用户 4–8 周积累 20+ 餐 [RICE 会话结论]），窗口内做了也测不出效果；AI agent 缩短不了日历时间 |
| **最大风险** | 人情效应污染信号（熟人给面子，次日回访虚高） | n=1 自访偏差 + 悲观链路：Reach 70% 是 RICE 排序最真实软肋（见头部悲观链路声明），若错则 MVP 直接空转 | 三线作战，任何一条验证不充分都浪费窗口；且 ⑤⑥ 在窗口内根本不可验证 |

### 决策：选 B，但把 A 吸收为 B 的第一周（M0 Wizard-of-Oz 阶段），并设 P0 开工前置闸门

理由：

1. **C 在本窗口内是伪选项**：P3 的验证依赖日历时间而非人力（RICE 会话已裁决），完整方案里最有差异化的部分恰恰是窗口内无法验证的部分。花 11+ 人周只能得到一个"没测过就上线"的复杂产品。
2. **A 单独做验证不到关键一跳**：A 能验证"愿意把决策交给工具"，验证不了"在无熟人压力的真实产品里愿意用它收口并去点单"。但 A 的成本低、且能提前行为级检验 RICE 最大软肋（Reach 70% [假设]，含悲观链路校准），因此不丢弃，作为 B 的 M0 前置，1 周内出方向性信号。
3. **B 直接承接 RICE 主攻结论**：P1 载体 + P2 最小内嵌（增量 ~2 人周，RICE 4,875 vs 1,080 的组合最优解）+ P3 探针。同时 B 在 M2 预埋了"P2 升格闸门"——敏感性分析显示 P2 乐观情景（4,140）逼近 P1，若 M2 信号显示约束匹配是质量上限所在，下周期主攻切 P2，不需要推倒重来。v3 补充（评审二 #4）：该排序在 Reach 悲观链路下可能反转，故 M0 行为校准优先于任何开发投入。

## 3. MVP 范围

### In（做）

1. **双路径收口流程（v3，评审二 #9）**：主路径"直接给答案"——0–1 题快选（如今晚预算 / 辣度）后即刻呈现 ≤3 家，终点是明确的"就这家"；可选深挖路径为 5–7 步单选题，引导浮现矛盾约束（有味不油 / 吃饱不撑 / 不贵不差 / 今晚想被治愈），是 P2 最小形态的载体；两路径均内置显式"随便吧"快捷出口——其点击即为可埋点的"投降式拍板"事件（§5 北极星口径依赖，评审一 #7）；任一步弃答即触发"直给 1 家"兜底并记录弃答步位（弃答率 20–40% 区间的明确应对动作）
2. **候选池筛选（外卖可得性优先，评审一 #5）**：候选池准入条件 = 当前时段**可配送至用户位置**。数据源由数据 spike（P0-3）裁定：目标商圈人工标注 50 家高德 POI 的"可外卖下单率"，≥80% [阈值假设] → 高德 POI 单源；<80% → 外卖平台店铺列表为主，或双源混合（外卖平台供可得性，高德补品类/位置元数据）。在准入池内做本次会话内约束→筛选映射（P2 最小形态）
3. **有限选项卡**：每次决策最多呈现 3 家，结构上禁止无限浏览（反"更多浏览"的产品立场）
4. **一键跳转点单**：深链/CPS 到外卖平台，兜底为店铺名 + 手动搜索；**深链每日心跳探活，失效自动切换兜底路径，失效期会话打"链接失效"标（评审一 #6）**
5. **饭后回访探针（P3）**：单问句"这顿怎么样"，**抽样触发——每人每周 ≤1 次（v3，评审二 #10）**，只积累数据不做界面，为下周期 P3 立项攒证据；触达方案与载体决策（P0-4）联动定稿：小程序 → 设计订阅消息授权点位（计入工期）；H5 → 改为"次日打开产品时自报"（评审一 #8）
6. **基础埋点（与 §5 指标逐条对齐，评审一 #7）**：会话起止、路径标识（直给/深挖）、逐题作答与步数、弃答步位、"随便吧"点击、逐推荐接受/拒绝、深链跳转事件及时间戳、链接失效标记、回访曝光与应答

### Out（明确不做）

1. 不做账号体系/注册（匿名本地标识即可）
2. 不做口味画像与个性化推荐算法（P2 完整形态，本期只做单次会话内匹配）
3. 不做个人餐历/历史沉淀的产品界面（P3 只留探针数据）
4. 不做内容社区、评价、探店（弱证据方向，问题卡已排除）
5. 不做午餐、社交聚餐场景（场景边界：只攻独食晚餐——最高频 + 最痛主战场）
6. 不做原生 App（只做小程序或 H5，双端原生是窗口外的奢侈）
7. 不自建店铺/菜品数据库（全部依赖第三方数据源——高德 POI / 外卖平台店铺列表，不自行维护与存储，见 §6 合规⑤）
8. 不做交易与支付闭环（跳转第三方，不做资金流）

总窗口 8–9 周（v3：含 0.5–1 周招募/重做缓冲，评审二 #11）；每阶段的信号阈值均为 [假设]，首测后按实际分布校准。

**P0 开工前置闸门（不满足不开工；评审一 #1/#2/#5、二 #1/#6/#11）**

- **P0-1 业务目标占位**（未决 #1 升格）：资助方明确下一周期方向——继续验证 / 变现 / 增长（粗粒度三选一即可）；未填则 M0 不启动
- **P0-2 招募落地**（未决 #3 升格）：确认 ≥1 个非同事、非密友的触达渠道；非熟人用户 ≥8 人承诺参与；招募截止日写入日程；用户须命中场景交集——工作日独食晚餐、外卖点单（评审二 #11）

> **样本量与判读规则（评审一 #1）**：本周期各阶段样本量均不支持 95% 置信的统计判别——n=10 时 60%/40% 阈值仅差 2 人，95% CI 宽约 ±30pp；A/B 检出 +10pp 需双臂各约 380 人（80% 功效），本周期不可达。因此上表所有阈值均为**方向性判读线**而非统计检验：验证记录每周随附 n 与 Wilson 95% CI；M2 采用序贯判读，预设最小可检测差异 MDE=15pp（v3，评审二 #7），结论明确标注为定向证据而非统计证明；任何闸门判定必须同时报告支持它的 n。

## 5. 成功指标

### 北极星指标：3 分钟内主动拍板率（应用内可观测口径，评审一 #7；v3 覆盖双路径）

定义：分子 = 打开产品后 **≤3 分钟内经任一路径（直给快选或答完全部题目）接受某一推荐并触发深链跳转**的会话；分母 = 打开并进入任一路径的全部会话。"随便吧"快捷出口或未完成即接受 = 投降式拍板，不计入分子。

- **基线**：10–15% [假设——自访外推：无工具时自然决策几乎均超 3 分钟，仅熟店兜底场景偶尔短于 3 分钟；n=1，待 M0 实测校准]
- **目标值**：M1 末 ≥50%，M2 末 ≥60% [假设]
- **子指标（§1 口径对齐）**：答题段中位时长 ≤90 秒（直给路径：打开→出推荐；深挖路径：打开→末题作答完成）
- **直给路径占比（v3 新增，评审二 #9）**：直给会话 ÷ 全部会话——主路径假设的过程指标，M1 只观测不设阈值

注：产品外行为（真实"跳回平台自刷"、平台内下单后的真实体验）在无账号体系下不可观测，一律以应用内代理或回访自报替代（见护栏 2 与探针），不做无依据的外推。

### 口径锁死与降级机制（v3 新增，评审二 #3）

满意度/将就类自报指标在 M1 上线前完成一次交叉校准：自报口径与 20% 抽样独立回访对比（与未决 #5 的单问句效度检验同场完成）；偏差 >15% [阈值假设] → 自报类指标降级为参考项，M2 的 P2 升格裁决改用埋点行为（答题完成率、跳转率、7 日回访率）；偏差 ≤15% → 维持自报口径并随附 CI。

### 护栏指标（防止为收口速度牺牲全局体验）

1. **饭后"将就/后悔"率**（质量护栏，对应问题卡"吃得将就、饭后反事实纠结"）
   - 分母 = **回访应答者**（存在应答选择偏差，数值仅代表应答人群；测量效度交叉检验与降级机制见未决 #5、口径锁死机制）
   - 基线：50–60% [假设——每周 3–4 顿将就 ÷ 5–7 次独食晚餐，n=1 外推]
   - 红线：>40% 即判定"更快地随便"，暂停追求速度；目标 ≤30% [假设]
2. **中途放弃率 / 旁路率**（体验护栏，防止题目变成新的负担；代理口径，评审一 #7）
   - 放弃 = 打开后进入任一路径但未完成即离开（应用内可观测）；弃答集中步位触发"直给兜底"优化（v3）
   - 旁路 = 答完全部题目、拒绝全部 ≤3 家推荐、且无任何跳转事件（真实"跳回平台自刷"不可观测，此为**下界代理**）
   - 红线：放弃率 >20% 或旁路率 >30% [假设阈值]，触发题目步骤与选项质量的回炉

### 供给与出口有效性（v2 新增，评审一 #5/#6）

- **首选项接受率**：首个推荐被接受并跳转 ÷ 完成答题会话（**剔除"链接失效"标记会话**）
- **深链两级漏斗**：跳转成功率（跳转事件 ÷ 接受推荐）→ 有效下单率；探活失效期内的会话不计入 M1 达标口径

### 最小经济性指标（v2 新增，评审一 #2）

- **CPS 深链有效下单转化率** = 有效订单 ÷ 跳转事件数（口径取自联盟后台）；个人主体 CPS 资质受限期间，降级为抽样自报核对
- M1 末建立基线；M2 末目标 ≥5% [假设，待联盟后台口径确认后校准]；M3 以此基线支撑收入路径候选集评估（v3，评审二 #2）

### 附：指标–埋点对照表（评审一 #7）

|---|---|---|

## 6. 风险与缓解

| 类别 | 风险 | 缓解 |
|---|---|---|
| **技术·供给数据轴**（v2 置顶，评审一 #5） | 高德 POI 是**到店轴**数据，不含"是否接外卖/配送范围/配送时长"；旗舰场景（在家独食点外卖，唯一行为级证据即此场景）下直接用作品类筛选，会稳定产出无法下单的候选，"手动搜索"退化为王路径，M1 首选项接受率 ≥50% 在数据结构层面不可达 | P0-3 数据 spike（50 家 POI 可外卖下单率）先行裁定数据源；候选池准入条件 = 可配送至当前位置；<80% 切外卖平台店铺列表或双源混合（§3 In-2） |
| **技术·匹配粒度与出口** | 高德/外卖平台均无菜品粒度，"有味不油"类约束只能落到品类级，匹配质量上限受限；深链到美团/饿了么不稳定或被平台封禁，且封禁可任意时点**静默发生** | 明示"品类级匹配"预期管理；兜底为展示店铺名 + 引导手动搜索；**深链每日心跳探活 + 失效自动切换兜底 + 会话打"链接失效"标，失效期数据不计入达标（评审一 #6）**；验收拆"跳转成功→有效下单"两级漏斗（§5） |
| **技术·载体**（v3 新增，评审二 #6） | 小程序审核被拒或周期超预期；H5 无推送能力削弱回访触达；若改用个人号群机器人承载，封号即种子用户/埋点/回访全部归零 | P0-4 载体裁决前置，默认小程序/H5，明确排除群机器人方案；降级路径：小程序被拒/超期 → H5；H5 下回访改为"次日打开产品时自报"（§3 In-5） |
| **采用** | RICE 最大软肋：Reach 70% 来自 n=1 自报 [假设]，悲观链路（每周 ~20 分钟总损失）下显著更低（评审二 #4）；若实际远低则无人可服务 | M0 Wizard-of-Oz 先行，用行为数据替代自报再决定是否投入开发；招募不限于熟人且已升格为开工前置 P0-2（渠道确认 + 非熟人 ≥8 人 + 截止日 + 场景交集），控制人情效应 |
| **竞争** | 大平台"帮你选/闭眼点"类功能**并非不会上线**——美团/点评早有"随便看看"入口，证伪了"平台因浏览时长变现结构不会做"的乐观假设（v3 修正，评审二 #2）；巨头凭渠道与数据优势随时可放大 | 押注平台中立（跨平台推荐、不卖流量位）建立"收口心智"；本周期为验证期，不做正面对抗。**监测机制（评审一 #3）：每两周一次固定检索（美团/饿了么/抖音版本更新日志 + 应用商店更新说明 + 行业媒体），负责人本人；黄色预警 = 任一巨头上线同类"帮你选"功能（记录并加测留存）；红色触发 = 黄色预警成立且 7 日留存连续两周下滑 ≥10pp，或首选项接受率下滑 ≥15pp [假设阈值] → 冻结后续投入，当期止步于验证报告，评估转型其上层中立层或停止；M1 做竞品截图实测复核其"收口完成度"，校准差异化空间（v3，评审二 #2）** |
| **合规** | ① CPS 佣金链接需平台联盟资质，个人主体可能受限；② 高德 POI 商用配额与条款；③ 饮食推荐涉及健康/过敏边界；④ 回访数据受个人信息保护法约束；⑤ **服务端缓存/存储 POI 数据可能与高德开放平台存储限制条款冲突（v2 新增，评审一 #9）** | M1 前完成：核对高德开放平台商用授权、免费配额与**数据存储条款** [假设：原型期配额足够]；**筛选架构优先端上实时拉取、不做服务端 POI 缓存/存储，规避条款冲突，spike 清单输出"端上实时拉取 vs 服务端缓存"选型结论**；CPS 走官方联盟或暂以无佣金深链上线；产品内加"特殊饮食需求请遵医嘱"免责说明；数据最小化——只存匿名标识 + 决策行为，不存任何身份信息 |
