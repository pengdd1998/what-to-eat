## 1. 项目一句话

> **「吃什么」是一个记得你口味、感知你所处情境的饮食决策助理——在你说不出想吃什么的时刻，用最少的步骤帮你心甘情愿地结束决策。**

---

## 2. 背景与机会

### 2.1 痛点真实且高频
- 目标用户一周爆发"不知道吃什么"** 5–7 次**（约每天 1 次）：工作日晚餐 3–4 次、工作日午餐 2–3 次、休息日 1–2 次（负责人亲测，待真实用户验证）；
- 单次决策成本：现有方案下用户平均要刷 **10–20 分钟**，且常以"耗不动了、随便点一个"收场，餐后无满足感、伴随反事实后悔。

### 2.2 现有方案结构性失职（机会所在）
| 现有玩家 | 结构性问题 | 对我们的意义 |
|---|---|---|
| 美团/点评 | 商业模式靠竞价曝光与信息流，**选择过载是TA们的广告库存，做减法等于砸自己生意**；以店铺为单位组织信息，而用户吃的是"这一餐" | 决策入口空缺，且大平台组织级矛盾短期难以跟进 |
| 探店内容（视频/博客） | 广告化，种草≠可靠 | 信任缺口 |
| "随便吃"类转盘工具 | 无记忆、无画像、纯随机 | 有场景无产品 |

### 2.3 技术时间窗
LLM 使三件事的边际成本骤降：意图理解（说不出口的多约束匹配）、个人画像建模（行为流→可读可改的口味画像）、菜品级知识抽取（供给库冷启动）。**这套能力组合在 3 年前做不成，在大平台手里做不顺。**

---

## 3. 用户与需求（基于内部采访，假设级素材）

### 3.1 目标用户
- **核心**：一二线 CBD/产业园 25–35 岁职场人，无暇做饭、被海量选择困住（待真实用户校准）；
- **潜在**：在校大学生。

### 3.2 场景矩阵
| 场景 | 定位 | 说明 |
|---|---|---|
| **独食治愈**（下班晚餐/休息日一人食） | **主战场** | 最高频+最痛点，用户愿意为决策付出成本，想被美食治愈 |
| 工作日生存（午餐） | 次战场 | 痛点每天存在但被"熟店/食堂"策略回避，最先收敛到 0 步 |
| 已有明确想吃的 / 跟随他人 / 就近就快 / 自己做饭 | **边界外，不做** | 立项即明确 |

### 3.3 核心抱怨（按深度排序）
1. **无个人味觉记忆（最深）**：平台以店铺为单位、用户吃的是"这一餐"，个人真实体验零沉淀——每次裸奔决策；
2. 信息过载：刷 20 分钟越刷越累；
3. 信任崩塌：刷单评价、广告探店、买来的排名；
4. 决策瘫痪：收藏一堆店，吃时想不起；
5. 千人一类：推荐全是连锁。

### 3.4 关键用户洞察（来自真实用户故事：22 分钟米线之夜）
> 18:12 瘫沙发 → 刷外卖 22 分钟（扔手机 2 次、开冰箱放弃、问朋友得到"随便"）→ 四组矛盾约束（有味↔不油 / 饱↔不撑 / 不贵↔不差）→ 18:34"耗不动了"随便点 → 将就吃完 → 饭后仍在想"换一家会不会更好"。

**产品启示**：用户要的不是"最好的答案"，而是**"尽快、心甘情愿地结束决策"**；纠结本质是多约束匹配问题，用户有判断力、缺的是替TA做全局匹配的机制；饭后缺决策闭环。

## 4. 产品定位与方案

### 4.1 定位陈述
- **前台形态**：多步选择题 + 有限优质选项卡（用户零学习成本）；
- **后台大脑**：LLM 情境引擎（LLM 管理解和表达，确定性系统管事实和交易，一切生成 grounded 在真实供给数据上）；
- **核心能力承载（v1.1）**：产品全部智能功能由 LLM 承载——情境收敛、画像蒸馏、回访抽取、理由生成、供给知识抽取；移除 LLM 即退化为普通选择题工具，差异化归零。LLM 服务不可用时自动降级为固定选择题模式（可用性保底，差异化暂失，见研讨文档 M0）；
- **三条产品红线**：情境必须可见（每卡一行情境理由）、误判必须可纠（换一批一键纠偏）、省略必须显式（"已根据口味默认 3 项"）。

### 4.2 三大核心资产

**① 情境引擎（空间维度：每次决策如何收敛）**
> 语境先验（地域/季节/天气气温/用餐时段/附近热销 → 定候选池）→ 个性偏置（口味画像 → 重排）→ 当场意图（选择题答案 → 过滤）→ 三张卡

- 三张卡职责分工：**稳牌**（画像最优解）+ **新牌**（防吃腻的邻域探索）+ **应景牌**（纯情境驱动）；
- "附近热销"必须经过 **热销 × 个人画像 × 菜品级可信度** 三重过滤，避免重造"千人一类"。

**② 收敛阶梯（时间维度：随画像变厚如何演进）**
| 阶段 | 画像 | 步数 | 用户感受 |
|---|---|---|---|
| L0 冷启动 | 空 | 5–7 步 | "比刷 22 分钟强" |
| L1 学习期 | 基础字段固化 | 3–4 步 | "它在记住我" |
| L2 熟练期 | 画像可预测 | 1–2 步 | "它懂我" |
| L3 托付期 | 高置信 | 0 步推送"今日三张卡" | "饭点等它投喂" |

- 步数递减由**字段置信度**驱动（硬约束忌口类绝不猜测）；画像含衰减机制防过拟合；独食治愈场景长期保留 1–2 步（仪式感）。

**③ 口味画像（数据底座/护城河）**
- 被动沉淀三信号：选项选择 + 复购行为 + 5 秒说人话回访（"汤偏咸但挺暖"→ 菜品级抽取）；
- 画像**可见、可聊、可改、可删**（"以后别推金针菇"立即生效）；
- 冷启动：首跑 30 秒口味闲聊 + 群体先验补位 + 保守广谱推荐（宁多问一步，不硬猜一次）。

### 4.3 供给侧方案（自认最大难题的破解路径）
- **变现与数据获取不依赖战略合作**：美团联盟/饿了么联盟现成 **CPS 分佣接口**导流变现；
- 店铺底库用**高德/百度地图餐饮 POI**，绕开美团依赖；
- 菜品级知识库：LLM 批量抽取公开评价/菜单的菜品属性 + 可信度过滤（识别刷单文风）+ 用户每餐记录反向众包。
- ⚠️ 前置调研项：附近"热销"数据的获取路径（联盟接口销量字段 vs POI 热度代理指标），P0 启动前必须落定。

## 5. 商业模式

| 项 | 方案 |
|---|---|
| 收入 | P0-P1：CPS 外卖/团购分佣（按单）；P2 后评估：应景卡的店铺曝光位（**克制**，不得破坏三张卡信任） |
| 成本 | LLM 调用（分层调度：小模型解析+大模型画像，画像缓存）、天气 API、地图 POI 配额、云资源 |
| LTV 逻辑 | 画像越厚 → 迁移成本越高 → 留存 → 日均 1 次决策 × CPS 转化 → 单用户分佣 LTV 上升 |

---

## 6. 竞争与壁垒

- **对美团/点评**：TA们的商业模式要求选择过载持续存在（做减法=砸广告库存），组织级矛盾难以抄袭；决策入口正是TA们分发漏斗的上游；
- **防抄袭**：护城河 = **跨平台中立的个人味觉记忆**（类比记账产品记所有平台的账）；大平台能抄"选择题+选项卡"的形，抄不走"用户托付给中立第三方的记忆"；
- **对小工具**：随机转盘无记忆无画像，不在同一层竞争。

## 8. 指标体系

| 层 | 指标 |
|---|---|
| 北极星 | **被托付的决策次数**（0 步推送一键采纳 + 低步数完成且餐后满意的决策） |
| 过程 | 收敛步数×使用周龄曲线；L0→L3 用户占比迁移；饭后回访沉淀率；周留存；决策总耗时 |
| 商业 | CPS 点击率/转化率/单用户分佣 |
| 反指标 | **饭后反事实思考率**（"换一家会不会更好"）；推荐拒绝率；画像焦虑相关投诉 |

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 供给侧数据不可得（热销/菜品） | 高 | CPS+POI+LLM 抽取三路并进；P0 前置调研落定热销路径 |
| 冷启动首因效应（画像薄硬猜→首周流失） | 高 | L0 保守广谱+热销锚点，宁多问不硬猜 |
| LLM 幻觉（推荐不存在的店=信任崩塌） | 高 | 架构原则：LLM 不碰事实层；推荐前逐条校验在营/可达 |
| LLM 战略依赖（模型能力/延迟/厂商锁定） | 高 | 评估基准集与回归测试**先于**功能建设；分层调度控成本与延迟；模型可替换架构，不绑定单一厂商；降级预案（退回固定选择题模式） |
| 被大平台抄袭 | 中 | 时间窗+跨平台记忆壁垒；快速积累画像 |
| 频率假设不成立（5–7 次/周为亲测） | 中 | P0 A/B 同步校准；真实用户小样本访谈立项后第一周执行 |
| 隐私/合规（忌口涉健康敏感信息） | 中 | 画像可见可改可删；数据合规口径上会确认 |
| LLM 成本 | 中 | 分层模型调度+画像缓存 |
| 画像焦虑 | 中低 | 省略显式化+画像透明 |

## 10. MVP 计划与里程碑

| 阶段 | 周期 | 内容 | 通过标准 |
|---|---|---|---|
| **P0 前置** | 第 1–2 周 | 真实用户小样本访谈（校准假设画像）；热销数据路径调研；CPS/POI 接口打通验证；**LLM 评估基准集（golden set）搭建** | 画像假设校准报告；供给路径落定；评估集可跑回归 |
| **P0 实验** | 第 1–2 月 | "LLM 情境引擎选项卡（L0/L1）" vs "无 LLM 固定选择题" vs "自由刷外卖"三方 A/B | 决策总耗时显著下降；餐后满意度不降；反事实思考率下降 → 过二次评审 |
| **P1 护城河** | 第 2–4 月 | 说人话回访 + 口味画像上线，飞轮启动 | 回访沉淀率、步数下降曲线达标（L1→L2） |
| **P2 供给** | 第 4–6 月 | 菜品级知识库 + 评价可信度过滤 | 菜品库覆盖率；推荐可信度指标 |
| 暂缓 | — | 社交聚餐决策 / 冰箱做饭场景 / 大学生市场 | 主场景验证后再议 |

## 11. 资源需求（待评审会核定）

- **团队**：PM×1、客户端×1–2、后端×1–2、**LLM 工程×1–2（核心岗：评估基准集、分层调度、画像管线）**、设计×0.5（P0 期最小配置）；
- **外部**：LLM API 预算（分层调度后预估单次决策成本待测算）、天气 API、地图 POI 配额、外卖联盟账号；
- **法务**：用户数据（位置/口味/健康相关忌口）合规口径。

---

## 12. 请评审会拍板的四个决策点

1. **是否批准实验型立项**：本材料建议只批 P0 资源，2 个月后凭三方 A/B 数据过二次评审——避免在未验证"更快结束决策"之前全量投入；
2. **供给侧路线**（CPS 分销 + 地图 POI + LLM 知识库，不依赖战略合作）是否认可；
3. **北极星指标口径**（"被托付的决策次数"的定义与埋点）是否确认；
4. **数据合规底线**（口味/忌口/位置数据的采集边界）是否确认。
