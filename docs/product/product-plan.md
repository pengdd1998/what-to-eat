## 2. 方案选项与选择

### 选项对比表

| 维度 | 选项 A：最小可行「纯收口器」 | 选项 B：收口器 ＋ 薄味觉记忆（**选定**） | 选项 C：完整「味觉决策引擎」 |
|---|---|---|---|
| 内容 | P1＋P3：打开即 ≤3 道自适应选择题 → 唯一结果 ＋「就吃这个」＋ 最多 2 次「换一个」；无记忆，每次冷启动 | A 的全部 ＋ P2 薄层：3 题冷启动画像、每次决策隐式反馈沉淀（设备本地标识，无账号）、内置 3–4 组经典成对约束（有味↔不油 / 饱↔不撑 / 不贵↔不差）作为生成约束 | B 的全部 ＋ P4 完整自定义约束系统 ＋ 全量味觉记忆模型 ＋ 餐厅数据库接入 ＋ 订阅支付 |
| 验证什么假设 | P1「低成本收口能让用户心甘情愿结束决策」；P3 交互预算（≤30 秒 / ≤5 步）技术可达 | A 的全部 ＋ P2「越用越准」能否驱动回流（使留存可测） | P4 多约束长期价值 ＋ P5 付费闭环 |
| 代价 | ~5 人周；放弃留存验证——无记忆则复用体验衰减，产品退化为一次性工具 | ~6.5 人周（＋缓冲/验证 1.5，总 ≤8 人周 [假设]；分解见文档头部），8 周窗内可发布 | ≥12 人周 [假设] ＋ 每用户 4–8 周日历时间记忆价值才能显效；**超出 8 周窗口，违背"发布测试"业务目标** |
| 主要风险 | 推荐始终平庸，北极星第 2 周起无从谈起 | 记忆层污染推荐，需可清空/衰减机制 | 在 n=1 证据上对置信度最低的 P4（RICE C=30%）做重资产 |

### 决策：选 B，B 即 §3 的 MVP 范围

理由：

1. **RICE 三轮一致收敛**于"P1 主攻、P3 内化为验收约束、P2 薄层供料"，B 是该结论的直接落地。
2. **不做记忆层则止损信号不可判读**：定稿问题卡 P2 明确"不解决则产品为一次性工具、无留存"——M2/M3 的继续/止损信号都依赖回流数据，选 A 等于花 8 周只验证"能用"不验证"值得做"，P5 风险原样保留。
3. **边际代价可控**：薄记忆层仅 +1.5 人周，总预算仍在 8 人周内。
4. **C 在本窗口是伪选项**：违背 8 周发布测试的业务目标，把最未验证的假设做成重资产，被"统计结论是唯一交付物"（ADR-001/002 共同前提）直接否决；C 中有价值的部分（P4 成对约束）已以窄化形态内嵌进 B。

### 与现有方案的对照：为什么"不知道吃什么"不算已被解决 [评审 #2]

| 现有方案 | 为何不算已解决 P1「耗尽投降」收口 |
|---|---|
| 美团/饿了么首页推荐、"随便看看"入口 | 平台按浏览时长与广告位变现 [假设：公开商业模式]，给的是"更多可逛"而非"就此收口"；排序含商业因素，与用户今晚的口味约束无关（竞争风险行已确认该入口存在，乐观假设已证伪） |
| 随机转盘 / 骰子类小工具 | 无口味记忆、无约束匹配，纯娱乐随机；"随机"≠"按我的口味收敛"，结果可用性低，用两次即弃 |
| 收藏夹 / 常吃清单 | 依赖预先维护，不复用当下状态（今晚想吃辣时帮不上忙）；维护意愿随时间衰减，正是 RICE 落选的"收藏黑洞" |
| 问朋友 / 发群 | 人情成本 ＋ 响应延迟；对方不了解我的口味历史，多数回"随便"——把决策压力原样退回 |
| 通用 AI 助手直接问"吃什么" | 无持久味觉记忆（每次重述口味）、无低成本交互预算约束（多轮对话恰是 P3 要消除的负担）、无跳转点单闭环 |

结论：现有方案覆盖"发现 / 娱乐 / 泛推荐"，未覆盖"≤5 步、唯一答案、记得口味、直达点单"的低能量收口——这是差异化空位。**本表为桌面论证，须在 M0 访谈中交叉验证**（用户被问"随便看看/转盘/AI 助手为何不够用"的真实回答），验证不过则回滚问题定义，不进构建。

## 3. MVP 范围

### In（做）

1. **核心收口流**：打开即问 ≤3 道自适应选择题（每题 ≤5 秒可答；**其中 1 题固定为"今晚生效约束"标签多选，见第 4 条** [评审 #9]），输出**唯一结果**（一道菜/品类 ＋ 一句情绪化推荐语）＋「就吃这个」＋「换一个」——上限分档：**稳态 2 次后强制收口；冷启动期（偏好档案有效信号 <5 次 [假设]）放宽至 3 次，或触发「都不行，再问我一轮」重问 1 题后重新生成** [评审 #10：冷启动推荐必然最不准，最需容忍的头几天恰是体验最差的天]
2. **交互预算验收（P3 内化）**：从打开到确认 ≤30 秒 / ≤5 次点击，是硬性验收标准而非优化项；**适用于稳态会话；冷启动会话（含放宽的换一与再问一轮）单列观测、不判失败，但须报告其占比与时长分布** [评审 #10 与 P3 的权衡显式化]；任一步弃答即触发"直接给 1 家"兜底并记录弃答步位
3. **薄味觉记忆（P2 薄层，规格化 [评审 #7]）**：3 题冷启动画像；隐式反馈信号枚举与写入权重——「就吃这个」=+1、「换一个」=−0.5、负反馈按钮=−1、弃答=0（不写入）、回访"不满意"=−1 [假设权重，M1 狗粮期校准]；仅保留最近 20 条滚动窗口 [假设] ＋ 指数衰减（半衰期 2 周 [假设]）＋ 一键清空，防记忆污染；设备本地标识，无账号；**anon_id 常设可见可复制 ＋ 口令恢复**（对齐实施方案 v2.0 安-2；留存锚点不单一依赖 webview 持久性）[评审 #4]；**菜品候选集规格**：LLM 时段预生成池 ≥200 道/城市·时段 [假设] ＋ 本地规则菜库 ≥50 道 [假设] 兜底，每周批量更新，负反馈菜自动剔除出池
4. **成对约束窄化形态（P4 内嵌，升级 [评审 #9]）**：3–4 组固定成对约束作为生成侧约束 ＋ **1 题"今晚生效约束"标签多选**（≥10 个固定标签池：不吃辣 / 想喝汤 / 不重样 / 预算 ≤30 / 清淡 / 重口味 / 想吃热乎 / 想吃冷的 / 要快 / 想慢享；固定标签非自由文本，实现成本近于原设计）；P4 处置口径 = **部分缓解**（窄化内嵌＋标签多选），完整自定义仍属 Out
5. **一键跳转外卖平台搜索该菜品**（不建餐厅数据库、不做 POI、不做菜品库；深链失效兜底 = 展示菜品名 ＋ 引导手动搜索，沿用每日探活机制）；**跳转即北极星记功点，平台侧真实下单不可观测，以回访自报下单率校正（见 §5）** [评审 #11]
6. **Umami 埋点（对齐 ADR-002）**：会话起止、逐题作答与步数、弃答步位、推荐接受/拒绝/换一（含换一耗尽标记）、**跳转双事件（点击「就吃这个」＋ 60 秒内跳转触发）**、链接失效标记、回访曝光与应答（含自报下单字段）、**假门漏斗（曝光/点击/登记完成）**
7. **P5 价值探针**：收口后单题 NPS / 打扰率（抽样触达 ≤1 次/人/周，不打扰主流程）＋ **付费意愿"诚实假门"**：展示定价锚点 X（未决 #2）＋ 明示"验证期免费、未来或收费" ＋ 意向登记按钮，记录 曝光→点击→登记完成 漏斗；不实际收费、不展示虚假促销 [评审 #3] ＋ **次日回访新增"跳过去之后真的点了吗"（自报下单率）** [评审 #11]
8. **载体与技术底座（既裁事项）**：H5（微信 webview 内投放），Python 薄 API ＋ SQLite；后端栈 Node/Go 单体 vs FastAPI/Python 按 ADR-001 于 W1 周五以 PoC 数据拍板

### Out（明确不做）

1. 餐厅数据库、菜品数据库、评价体系、任何爬取/对抗刷评（RICE 轮 2 已裁定"数据战争"无胜算）
2. 用户自定义约束系统（P4 完整形态——指自由文本/任意组合；In 第 4 条的固定标签多选不属此列）
3. 账号体系、注册登录、跨端同步、订阅支付
4. 消息推送/定时提醒（ADR-002 裁定放弃，回访靠"次日打开自报 ＋ 群内人肉轻推"）
5. 午餐、社交聚餐场景（问题卡已丢弃）；多城市运营配置（MVP 仅服务负责人所在一线城市）
6. 内容社区、探店、"千人一面"式大众推荐（用户未表达为自身痛点）
7. 交易与资金流（跳转第三方，无 CPS 佣金——资质问题推迟到 M3 收入路径评估时再核）

## 4. 里程碑与验证点

总窗口 8 周；各阶段阈值均为 [假设] 的**方向性判读线**而非统计检验（样本量不支持 95% 置信判别，见表后判读规则）。

| 阶段 | 交付物 | 验证假设 | 继续信号 | 止损/转向信号 |
|---|---|---|---|---|

> **样本量与判读规则（继承 v3，评审 #1/#8 扩充）**：本周期各阶段样本量均不支持 95% 置信的统计判别——n=10 时 60%/40% 阈值仅差 2 人，95% CI 宽约 ±30pp。上表所有阈值均为方向性判读线：验证记录每周随附 n 与 Wilson 95% CI；M2 及以后的对比采用序贯判读（MDE=15pp [假设]），结论标注"定向证据"而非统计证明；任何闸门判定必须同时报告支持它的 n。**灰区动作写死**：任一指标介于继续/止损阈值之间 → 固定动作 = 延长观察 1 周 ＋ ≥5 人定性访谈，复判后二选一。**小样本定性优先**：有效判定样本 <15 人时，闸门判定以定性结论为主、数值仅作方向参考；15–30 人时数值仅方向性判读 ＋ 定性交叉。**人均频次型指标的 MDE**：n=30 时人均 ±0.1 次/周 ≈ 3 人改变每周 1 次行为；北极星闸门（M4）须以连续 ≥2 周稳态数据＋逐人分布判读，禁止以单周均值定夺。

## 5. 成功指标

### 北极星指标：周活跃用户人均「主动收口」次数（原「心甘情愿收口」，更名以贴合可埋点口径 [评审 #1]）

定义（**全埋点判定，无主观字段**）：分子 = 周内"主动收口会话"数——会话内点击「就吃这个」**且 60 秒内触发跳转外卖平台**（双埋点事件），且非投降路径（强制收口后接受、弃答兜底接受不计入分子，单列观测）；分母 = 周活跃用户数。原 v4 分子中的"次日回访未标记负反馈"**移出分子**——回访应答率低时该条件要么虚增（未应答视同满意）要么缩样（剔除未应答），两者都留有事后解释空间，负反馈改由护栏 2 与校正系数承担。注：评审建议示例中的"未点换一个"不纳入分子条件——换一后主动接受仍属主动收口，首推接受率已由护栏 1 单独守护。

- **基线**：上线前 = 0（产品不存在）；现状参照基线 = 目标用户晚间决策 3–4 次/周·人 [假设]，单次耗时 10–22 分钟、以「耗尽投降」收场（n=1 唯一行为证据，占比 ~90% [假设]）
- **目标值**：公测第 4 周（M3 末）≥1.5 次/周·人，复盘闸门（M4）≥2.0 次/周·人 [假设：取可服务频次的约 60%]（判读方式受 §4 规则约束）
- **过程子指标**：决策时长中位 ≤60 秒；会话步数中位 ≤5 步（P3 验收值）
- **校正 [评审 #11]**：北极星在"跳转"记功，平台侧真实下单不可观测——以回访新问句"跳过去之后真的点了吗"的自报下单率作校正系数：**真实收口完成率 ≈ 北极星 × 自报下单率**；本期无 CPS，自报口径为唯一定期校正，不做无依据外推

### 护栏 1（决策质量分）：首推接受率

0 次「换一个」直接收口的占比 ≥50% [假设]；辅助监测 7 日内重复推荐占比 ≤30% [假设]。防止为刷收口次数输出保守重复的平庸答案，把「耗尽投降」换皮成「算法投降」。基线：无历史数据（素材自述盲区），M1 本人使用时首建。

### 护栏 2（负向/打扰率）：收口后单题中「没用 / 反感 / 打扰」占比 ≤10% [假设]

并以「会话步数中位 ≤5 步、决策时长中位 ≤60 秒」为 P3 硬红线（设计验收值，非假设）。防止为完成率重新引入主动打扰——本 MVP 无推送（ADR-002 裁定），依赖"次日打开自报 ＋ 群内轻推"。基线：0（盲区），M2 种子期首建。

### 护栏 3（收口哲学）：换一耗尽率 [评审 #10]

定义：达到「换一个」上限仍未收口的会话占比（冷启动/稳态分桶统计，M1 狗粮日志起持续记录）。红线：**冷启动期（有效偏好信号 <5 次 [假设]）耗尽率 >30% [假设]** → 判定"强制收口"在该用户群失效，触发放宽策略与生成质量复盘；稳态耗尽率 >20% [假设] → 生成质量回炉。防止"最多 2 次换一"在推荐最不准的头几天透支用户信任。

### 附：指标–埋点对照

| 指标 | 计算口径 | 依赖埋点事件（Umami） |
|---|---|---|
| 北极星（主动收口次数） | 点击「就吃这个」＋60 秒内跳转的双事件会话 ÷ 周活跃用户 | 推荐接受、跳转事件、会话起止 |
| 决策时长 / 步数 | 打开 →「就吃这个」 | 会话起止、逐题作答、推荐接受 |
| 首推接受率 | 0 次换一直接收口 ÷ 完成会话 | 逐题作答、换一、推荐接受 |
| 重复推荐率 | 7 日推荐去重占比 | 推荐曝光内容标识 |
| 负向/打扰率 | 回访应答中负向占比 | 回访曝光、回访应答 |
| 换一分布 / 弃答步位 / **换一耗尽率** | 质量诊断；耗尽率 = 达换一上限未收口会话 ÷ 完成会话 | 换一（含耗尽标记）、弃答步位 |
| **自报下单率** | 回访应答中"点了"占比 | 回访曝光、回访应答（新字段） |
| **假门漏斗** | 曝光 → 点击 → 登记完成 转化率 | 假门曝光/点击/登记 |

注：产品外行为（跳回平台自刷等）在无账号体系下不可观测，以应用内代理或回访自报替代，不做无依据外推。
