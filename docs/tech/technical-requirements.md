# 【吃什么】技术需求文档（TRD v2，对齐规划 v4.1）

> 转写来源：`docs/product/product-plan.md`（v4.1 评审修订版，2026-09-02）｜转写日期：2026-09-02
> 团队环境：1 人 ＋ AI agent；Docker 部署（既有环境给定，非选型结论）
> 本文只做需求转写与量化，**不做任何技术选型**；规划自身遗留的分叉（后端栈、webview 持久性、LLM 供应商）以"待裁定"形式呈现，裁定权仍在 ADR-001 / E-PoC-1 / 未决 #6 流程。
> 标注约定：`§n` = product-plan.md 章节；`[假设：待产品确认]` = 规划推不出、由本转写给出的量化建议值；`[推断：来自常规工程实践]` = 规划未提、技术上必须有的项。
> 文档治理（评审 #5）：本文件即"TRD v4 对齐同步"的交付物；旧 TRD v1（转写自规划 v2）已归档至 `docs/archive/technical-requirements-v1.md`。`product-roadmap.md` 与 `implementation-plan.md` 两份的 v4 对齐**仍待完成，未完成不进 M0 构建**（§头部·文档同步）。
> 范围说明：M0（W1）为微信群人肉 A/B ＋ PoC spike，除"栈骨架 PoC ≤3 人日端到端走通"外**零工程系统**（§4 M0）；下表功能需求自 M1 构建起算。

## 一、功能需求清单

| 编号 | 需求 | 来源 |
|---|---|---|
| FR-01 | 自适应问卷流：打开即问 ≤3 道自适应选择题，每题 ≤5 秒可答 | §3 In-1 |
| FR-02 | "今晚生效约束"标签多选题：固定为问卷中的 1 题；标签池 ≥10 个固定标签（不吃辣 / 想喝汤 / 不重样 / 预算 ≤30 / 清淡 / 重口味 / 想吃热乎 / 想吃冷的 / 要快 / 想慢享）；固定标签，**禁止自由文本输入** | §3 In-4、评审 #9 |
| FR-03 | 唯一结果输出：一道菜/品类 ＋ 一句情绪化推荐语 ＋「就吃这个」＋「换一个」两个操作 | §3 In-1 |
| FR-04 | 换一分档上限：稳态 2 次「换一个」后强制收口；冷启动期（偏好档案有效信号 <5 次 [假设]）放宽至 3 次，或触发「都不行，再问我一轮」重问 1 题后重新生成 | §3 In-1、评审 #10 |
| FR-05 | 冷启动/稳态判定：按用户偏好档案有效信号次数分桶（<5 次为冷启动 [假设]），供换一上限与耗尽率分桶统计共用 | §3 In-1、§5 护栏 3 |
| FR-06 | 弃答兜底：任一步弃答即触发"直接给 1 家"兜底，并记录弃答步位 | §3 In-2 |
| FR-07 | 交互预算测量与验收报告：稳态会话从打开到确认 ≤30 秒 / ≤5 次点击为**验收测试项**（非优化项）；冷启动会话（含放宽换一与再问一轮）单列观测、不判失败，须报告其占比与时长分布 | §3 In-2、评审 #10 |
| FR-08 | 3 题冷启动画像：新标识首次使用时采集 | §3 In-3 |
| FR-09 | 隐式反馈权重写入：「就吃这个」=+1、「换一个」=−0.5、负反馈按钮=−1、弃答=0（不写入）、回访"不满意"=−1（权重 [假设]，M1 狗粮期校准） | §3 In-3 |
| FR-10 | 记忆管理：仅保留最近 20 条滚动窗口 [假设] ＋ 指数衰减（半衰期 2 周 [假设]）＋ 一键清空（防记忆污染） | §3 In-3 |
| FR-11 | 匿名身份与恢复：设备本地标识 anon_id（无账号体系）；anon_id 常设可见、可复制；口令恢复为**常设能力**（非仅降级分支）；M1 狗粮期完成 ≥2 次清缓存/换设备的恢复演练 | §3 In-3、评审 #4、§4 M1 |
| FR-12 | 菜品候选集：LLM 时段预生成池 ≥200 道/城市·时段 [假设] ＋ 本地规则菜库 ≥50 道 [假设] 兜底；每周批量更新；负反馈菜自动剔除出池 | §3 In-3、评审 #7 |
| FR-13 | 成对约束生成侧：3–4 组固定成对约束（有味↔不油 / 饱↔不撑 / 不贵↔不差）作为生成侧约束 | §3 In-4 |
| FR-14 | 一键跳转外卖平台搜索该菜品；深链每日探活；失效兜底 = 展示菜品名 ＋ 引导手动搜索，并对该会话打"链接失效"标记 | §3 In-5 |
| FR-15 | Umami 埋点事件全集：会话起止、逐题作答与步数、弃答步位、推荐接受/拒绝/换一（含换一耗尽标记）、**跳转双事件**（点击「就吃这个」＋ 60 秒内跳转触发）、链接失效标记、回访曝光与应答（含自报下单字段）、假门漏斗（曝光/点击/登记完成）、推荐曝光内容标识（供 7 日去重计算） | §3 In-6、§5 附表 |
| FR-16 | 收口后单题 NPS/打扰率探针：抽样触达 ≤1 次/人/周，不打扰主流程 | §3 In-7 |
| FR-17 | 付费意愿"诚实假门"：展示定价锚点 X（未决 #2）＋ 明示"验证期免费、未来或收费" ＋ 意向登记按钮；记录 曝光→点击→登记完成 漏斗；**不实际收费、不展示虚假促销与虚构原价** | §3 In-7、§6 合规、评审 #3 |
| FR-18 | 次日回访问句："跳过去之后真的点了吗"（自报下单）＋ 满意/不满意；自报下单率作为北极星校正系数（真实收口完成率 ≈ 北极星 × 自报下单率） | §3 In-7、§5 校正、评审 #11 |
| FR-19 | 指标统计与独立复算：北极星（双事件口径，见 NFR/HC）、首推接受率、7 日重复推荐率、负向/打扰率、换一耗尽率（冷/稳态分桶）、自报下单率、假门漏斗、决策时长/步数分布（冷启动单列）、弃答步位分布、anon_id 标识存续率诊断；每次闸门判定同报 n 与 Wilson 95% CI；M2 起序贯判读（MDE=15pp [假设]）；M3 北极星统计报告须**独立于线上看板复算** | §4 判读规则、§5 附表、评审 #1/#4/#8 |
| FR-20 | 合规呈现：隐私声明；"特殊饮食需求请遵医嘱"免责说明；生成内容**禁止输出健康/减脂类建议** | §6 合规 |

## 五、复杂度风险点（最影响架构的三个不确定点）

### RSK-1　微信 webview 本地标识的 30 天持久性（未决 #5 / spike E-PoC-1，W1）

**分叉**：实测清除率决定记忆层与用户识别的两种架构形态——
- A：标识可持久 → localStorage/cookie 常驻，味觉记忆自然跨会话延续，口令恢复仅为备份手段；
- B：不持久 → 退化为"会话内记忆 ＋ 口令恢复为主锚"，anon_id 常设可见可复制（FR-11）从备份升格为身份主链路。

**连锁影响**：北极星**分母**（周活跃用户的跨会话识别）、M2 回流判定（标识被清 → 老用户误判为新用户、系统性低估回流，故规划要求附"标识存续率诊断"）、护栏 3 的冷/稳态分桶、候选池负反馈剔除的持久性——身份锚不稳，所有"周"口径指标的地基都晃。**技术动作**：身份锚必须抽象为可切换双形态的接口；W1 内出 30 天清除率实测数据。

### RSK-2　LLM 生成链路的延迟/成本/质量三角与预生成池覆盖率（未决 #6，W2 前定）

**分叉**：预生成池按"城市 × 时段"预生成（≥200 道），但真实请求空间是 时段 × 今晚标签的任意多选组合（10 标签 → 2^10 组合）× 3–4 组成对约束 × 个人记忆负反馈剔除——
- 池命中率高 → 后端近似"静态池 ＋ 薄 API ＋ SQLite"，生成服务近乎无状态，双预算轻松满足；
- 命中率低 → 大量实时生成，P95 ≤3 秒 与 ≤$50/月 双预算立刻紧张，被迫走降级路径（预生成占比上调/本地菜库权重上调）；极端情形触发 HC-2 的整体降级（规则引擎＋本地菜库，M0 PoC 超时即激活）。

**连锁影响**：双供应商抽象层、缓存策略、低温度模板化生成的模板管理、单次成本上限与月成本复核（SUP-03/SUP-04 依赖调用日志）。这决定后端是"静态池服务"还是"实时生成服务"——是本次最大的架构分叉，且必须在 W2 前定。

### RSK-3　跳转双事件的 webview 可观测性（§5 北极星分子 / §3 In-6）

**分叉**：「60 秒内触发跳转」事件发生在页面即将离开 webview 上下文的瞬间，两条实现路径——
- 纯前端方案：点击后以 unload/beacon 类机制补发事件——零额外组件，但微信 webview 内此类发送的可靠性**未知**，丢事件 = 北极星分子系统性低估；
- 服务端跳板路由：点击 → 先回自家服务端 302 → 再跳外卖平台——事件 100% 可记，但增加一跳延迟（挤占 30 秒预算）并引入微信拦截外链的新风险面。

**连锁影响**：北极星分子、自报下单校正系数的分母、"跳转即记功"的全部口径。统计结论是唯一交付物（HC-7）——**口径误差不是统计问题，是架构问题**，埋不准则 M3/M4 全部闸门判读失真。**技术动作**：W1–W2 在真机微信 webview 上实测 beacon 发送可靠性后再定架构。
