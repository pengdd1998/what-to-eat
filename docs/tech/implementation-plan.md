## 1. 架构总览

### 1.1 组件与数据流（形态无关骨架）

**FastAPI 单体：单仓、一份镜像、单库文件。** Docker Compose 4–5 容器（视 Umami 分支），需人运维的活动部件 3–4 个：api + cron（+ umami + umami-db）；caddy 为无状态边缘（TLS、反代、静态兜底页，**公网 `/api/admin` 一律 403**，评审 8），配置冻结、故障即重启。前端为 **Jinja2 SSR**（ADR-003 A 卡 D8=9 的依据：SSR 使前端 JS 面最小、无 SPA 构建链；HC-3 四项不变）。

- **api 容器（FastAPI + Jinja2 SSR）**：页面（隐私弹窗 → 冷启动画像 3 题〔FR-08〕→ ≤3 题自适应问卷〔FR-01，1 题固定标签多选 FR-02〕→ 唯一结果＋情绪化推荐语〔FR-03〕→「就吃这个」/「换一个」/「都不行，再问我一轮」〔FR-04〕→ 弃答兜底〔FR-06〕→ 跳转/兜底页〔FR-14〕→ 免责声明〔FR-20〕→（M2 起）收口后单题探针〔FR-16〕→（M3）诚实假门〔FR-17〕）＋ 纯 JSON API（会话、推荐、跳板、埋点、回访、身份、健康、Admin）。页面路由只做渲染，业务全部走 API——API/UI 第一天强制分层。
- **推荐策略模块（形态开关所在，唯一按终裁分叉的模块）**：`RecommendationStrategy` 接口 ＋ 两实现；`config.form = "A" | "C"` 切换＝**代码级开关切换＋一次发版（~3D 还债口径见 D-5），非热切换（v3.1，评审 1）**：
  - **A 实现（PyThin）**：请求（时段×今晚标签组合×记忆剔除）→ 查 `dish_pool`（预生成池，本地读 P99 ≤1s [假设]）→ 命中即出（菜品＋按组合预生成的推荐语）；未命中 → 冷启动实时生成模块（LLM 实时调用，P95 ≤3s、硬超时 6s，超时/失败切 `dish_library` 直给）。
  - **C 实现（RuleFloor）**：请求 → 规则打分 over `dish_library`（标签匹配＋成对约束 FR-13＋记忆降权）→ 空集放宽级联（全失配 → 仅时段＋记忆，C卡 C-R2）→ 模板推荐语（`template_copy`）；「再问一轮」退化为池内重排（C卡 D4=5 已声明的保真上限）。
  - **两形态共同的降级链**：LLM 不可用 / 池未命中 / 规则空集 → 本地菜库兜底（计为功能降级可用，单列观测，不算不可用）。**实时占比上调、全局兜底开关等终裁形态内的 config 项才是 ≤1 分钟热生效**。
- **cron 容器（Alpine ＋ sqlite3/psql ＋脚本）**：① 02:00 日表聚合（FR-19）；② 03:00 备份（app.db `.backup`＋Umami 库条件分支，§2.5）；③ 15:30 深链探活（核心时段 17:30–21:30 [假设，U6] 前完成，FR-14，含 1–2 个对照 URL 判探活器自身故障，SUP-05）——**"全红且对照绿"时自动置全局兜底 config 标志＋P1 告警，人工次日复核（v3.1，评审 15：把半夜决策从人身上摘掉）**；④ 23:59 LLM 成本/用量日结＋Umami 对账（SUP-03/04）；⑤ 每周一 04:00 LLM 周更批产管道（→ 人工抽检 → 激活，SC-7；产出物随形态：池内容 / 菜库富化＋模板语料）。cron 直写 SQLite（同机 WAL 多进程安全；写入语义 2026-09-04 勘误，工程审查 W-10：cron 不 UPDATE/DELETE 业务事实表〔events/sessions/memory_events〕，聚合/配置/探活/池生命周期表允许 upsert 与兜底翻转——探活自动置全局兜底与批产激活属设计内行为）。
- **Umami ＋ umami-db 容器（条件组件，SC-6）**：仅作原始事件副本＋流量面板。**口径单一事实源在自家 SQLite**；Umami 转发＝**按 SQLite events 表游标重放（v3.1，评审 12：无独立队列概念——进程重启不丢在途事件，天然可补发，与"SQLite 唯一口径源"自洽）**。T0.7 预验（§7），集成税 >1 人日或关键字段丢失 → 组件级降级自研 ingest（不换载体，SC-6）。
- **302 跳板（RSK-3 的默认解）**：点击「就吃这个」→ `POST /accept`（服务端记 accept 事件＋server_ts）→ 返回 `go_token`（HMAC 无状态签名，TTL 10 分钟 [假设]）→ 前端 `GET /go/{token}` → 服务端记 jump 事件（**100% 服务端可记；以 token 哈希为幂等键、同 token 首个 jump 生效，刷新/转发不重复计数，v3.1 评审 13**）→ 302 外卖平台搜索深链。北极星双事件 60 秒窗口＝两事件 server_ts 差（SUP-06 服务端时钟）。W1 PoC-3 真机验证（到达率 ≥95%、P50 ≤300ms，**第 0 步＝确认微信 webview 内域名可正常打开——ICP 备案前提，评审 6**）；失败 → 切前端 beacon＋服务端会话关联（＋2 人日，ADR-003 重评条件 6）。

**数据流（一次稳态会话）**：打开 → `session/start`（localStorage anon_id，RSK-1 双形态身份锚）→ 判冷/稳态（FR-05）→ ≤3 题（每题 `answer`）→ `result-request` → 推荐策略出唯一结果（池命中 P99 ≤1s / 实时 P95 ≤3s / 兜底）→ 呈现 → 换一（≤2 次）或再问一轮（冷启动 ≤3 次档）→「就吃这个」→ accept＋跳板 302 → 平台搜索；隐式反馈同步写记忆层（FR-09 权重）→ 会话埋点批量上报（SQLite 权威＋Umami 游标转发）。30 秒预算分解（TRNFR [假设]）：首屏 ≤2s（SSR 无 bundle）＋3 题作答 ≤15s＋生成等待 ≤3s＋缓冲 10s。

**统计出数流**：cron 日表 → 周报 SQL＋CSV 导出 → Wilson 95% CI 双实现（生产 Python ＋ pandas 独立复算，复用 PoC-1 仿真 harness）→ M3 北极星报告独立复算（HC-7）。

## 2. 数据模型与存储设计

### 2.1 核心实体（SQLite WAL 单文件 `app.db`；FR-15 事件全集为埋点权威）

**全局菜品键（v3.1，评审 2；2026-09-04 勘误，工程审查 W-11）**：`dish_pool` 与 `dish_library` 共同携带 `dish_slug`（规范化菜名 slug）作为跨表全局键——dish_pool 的唯一性为实现层组合唯一 `(time_slot, tag_combo, dish_slug)`（0003_full_tables.sql uq_pool_slot_combo_slug；原文"UNIQUE"表述不准确，组合唯一才支撑 200 道×组合扩展），dish_library 仍为 slug 单列唯一；`memory_events.dish_ref` 引用 slug 而非表内自增 id——形态切换（D-5 还债或 D10 升级）后，旧形态积累的 accept/swap 记忆信号可无损映射到新形态主数据，记忆层跨形态可迁移（T1.8 验收项）。

| 表 | 关键列 | 说明与回链 |
|---|---|---|
| `sessions` | `id`、`anon_id`、`status`(started→answering→presented→accepted/swapped_out/abandoned/timeout)、`is_cold_start`、`swap_count/swap_limit`、`form`、`started_at/ended_at`(服务端) | 冷/稳态分桶（FR-05）与耗尽率口径的地基 |

### 2.2 一致性要求

- **北极星判定 100% 服务端**：accept 与 jump 双事件的 `server_ts` 差 ≤60 秒（HC-10/SUP-06）；前端时钟仅存档。跳板 token 无状态 HMAC（session_id＋时间戳＋密钥），不落库、事件即档案；**jump 以 token 哈希为幂等键、首个生效（v3.1，评审 13：刷新/群转发不重复计数，北极星不可被无意识刷高）**。
- **埋点权威与副本**：SQLite `events` 为唯一口径源；Umami 为**events 表游标重放式异步副本（v3.1，评审 12：无独立队列——api 重启不丢在途事件，断流后从游标补发）**，最终一致，断流 ≤24h 告警 SUP-04，日结对账差异 >1% [假设] 告警。Umami 丢失不污染统计（HC-7）。
- **持久性**：`synchronous=FULL`＋WAL；写入频率极低（§2.3），换崩溃零丢失（RPO 语义）。
- **幂等**：`client_event_id` 唯一约束，批量重试安全；`busy_timeout=5s`；决策与记忆写入同事务（accept/swap 与 `memory_events` 原子）。
- **口径单一事实源**：全部闸门指标计算收敛在日表生成器一处；周报、导出、M3 独立复算只读日表或从 `events` 重放。

### 2.5 备份与恢复（SUP-01）

### 3.2 发布策略（合并→上线 ≤30 分钟，SUP-09）

trunk-based 短分支；镜像 tag＝git sha；发布窗**周二 14:00–17:00**（核心时段 17:30–21:30 [假设 U6] 内禁止变更，P1 故障除外）。**节假日条款（v3.1，评审 18）：假期内发布窗顺延至次一个周二；国庆周（10/1–10/7）不排发布**。

| 步 | 动作（执行人＝本人） | 耗时 |
|---|---|---|
| 1 | merge → tag | 2 分钟 |
| 2 | 本地 build＋冒烟脚本（compose 起→端到端：session→3 题→结果→accept→/go 302→双事件落库校验→换一/弃答路径→探活表可写） | 10 分钟 |
| 3 | 镜像推送 / 服务器 pull | 3 分钟 |
| 4 | `docker compose up -d`＋`/api/health` 绿 | 3 分钟 |
| 5 | 真机微信 webview 手工冒烟（4G [假设]） | 7 分钟 |
| 6 | audit_log 发布记录（含回滚点） | 2 分钟 |

### 3.3 数据迁移（绿地＋前向 only）

首部署＝`migrations/0001.sql` 初始化；后续 expand-only（加表/可空列，禁 rename/drop/改型）——保证旧镜像可跑新 schema、回滚不动库；迁移脚本顺序编号，发布步骤 2 中对生产库副本预演。9 周内预计 schema 变更 ≤3 次 [假设：迭代以 config 为主]。第 3 次变更 → 引入正式迁移框架（D-10）。

### 3.4 回滚动作序列（≤10 分钟）

| 步 | 动作 | 耗时 |
|---|---|---|
| 1 | 按 §5.2 runbook 判级：先 restart、后 rollback、最后 restore | ≤2 分钟 |
| 2 | `IMAGE_TAG=<上一稳定 tag> docker compose up -d`（库不动） | 3 分钟 |
| 3 | health 绿＋冒烟 3 题＋302 一跳 | 3 分钟 |
| 4 | audit_log 回滚记录 | 2 分钟 |

**数据损坏路径（RTO ≤4h）**：compose down → 备份完整性校验（`PRAGMA integrity_check`）→ 替换库文件 → up → 冒烟；按 §2.5 演练脚本执行。

**开关语义两层（v3.1，评审 1）**：**全局兜底开关与终裁形态内的组件级 config（实时占比、标签池文案等）＝Admin API 一键、≤1 分钟生效、audit 留痕——半夜止损可用**；**形态切换（`config.form` A↔C）＝D-5 还债 ~3D＋一次完整发版流程（build→冒烟→发布），不是分钟级动作**——runbook 与 RSK-2 预案（§5.1）均按此口径，避免操作者误判可秒切。

## 4. 安全设计

### 4.1 认证与授权

- **用户侧**：无账号（HC-5 Out）。身份＝localStorage anon_id（RSK-1 形态 A）＋**口令恢复常设能力**（FR-11：anon_id 常设可见可复制；口令加盐单向哈希存 `identity`，换设备/清缓存可找回——身份主锚在 webview 不持久时升格，形态 B）。**口令策略（v3.1，评审 7）：≥6 位、服务端拒绝弱口令（Top-1000 表＋纯数字）；recover 连续 5 次失败锁 24h（`recovery_count` 消费）；`/api/identity/passcode` 独立限流 ≤5 次/分/IP——防弱口令枚举劫持画像与记忆**。
- **限流与熔断（SUP-03）**：单 IP 60 req/min [假设]；单 anon_id 会话数护栏 10/天 [假设]；埋点批量 ≤50 条/批；**LLM 日调用/日费用双熔断**（阈值 W2 前随未决 #6 落定，超限自动切池/菜库并告警；公测期临时上限预案见 §2.3 M3 成本行）。
- **Admin 面**：`ADMIN_TOKEN`（≥64 字符随机，环境变量注入）＋**实现层双保险（v3.1，评审 8）：Caddy 对公网 `/api/admin` 返回 403；api 的 admin 路由只监听内网端口（127.0.0.1/内网 IP），公网连接层面不可达，静态 token 是第三层而非唯一层**；全部调用写 audit_log（单人团队最小充分方案，D-3）。T1.10 演练含"外部 curl `/api/admin` 必须 403"验收项。

### 4.2 数据分级与合规要点（HC-4）

| 级别 | 内容 | 处置 |
|---|---|---|
| L0 公开 | 题目/标签池/模板文案/兜底页 | 无限制 |
| L1 匿名行为 | sessions/events/记忆/画像/池与菜库/统计 | TLS 全站；仅匿名标识关联；导出走 Admin 鉴权 |
| L2 运维敏感 | 口令哈希、ADMIN_TOKEN、LLM key、备份、audit/llm_calls、age 私钥（仅本地设备，§2.5） | key 仅服务端环境变量（SUP-02，禁入前端/入库/入 git）；备份加密 |
| PII | **无**（数据最小化：匿名标识＋决策行为；**假门登记仅点击事件、零联系字段，v3.1 评审 10——如产品日后需要联系方式，本行升级并纳入 U8 法务自查**） | — |

合规件落地：首访隐私弹窗 100% 覆盖（含匿名说明、口令用途、一键清空）；免责声明"特殊饮食需求请遵医嘱"；**生成侧健康/减脂建议拦截**（prompt 约束＋输出关键词黑名单双层，FR-20，漏网即 D-13 还债）；**LLM 传输 PIPL**：批产为聚合口径；A 形态冷启动实时路径仅传脱敏上下文（标签＋匿名口味摘要＋日轮换假名 [假设]，不传 anon_id 原文）；**假门诚实原则**（明示验证期免费、不虚构原价/促销，FR-17）；假门文案与隐私文案 W2 法务口径自查留档（U8）。出境评估随未决 #6 供应商定稿一并闭合（X1）。

### 5.2 半夜/离线报警第一响应 runbook（执行人＝本人）

1. **定性（1 分钟）**：不可用 / 探活自动兜底已触发 / Umami 断流 / LLM 熔断 / 备份失败 / 磁盘。
2. **非核心时段非 P1 → 记录次日处理**（核心时段月不可用预算 ≤1.2h，NFR）；备份失败例外：当下 5 分钟手动 `.backup` 验库可读（03:30 告警已兜住"静默失败"，评审 11）。
3. **核心时段不可用（P1）**：`compose ps` 定位 → restart app（3 分钟）→ 不恢复按 §3.4 回滚（10 分钟）→ 疑库损坏按 §2.5 恢复（RTO 4h 内）。止损优先于根因——会话不可重放。
4. **LLM 熔断/实时不可用**：确认降级链已自动切池/菜库（功能降级可用，非事故）；次日复核 `llm_calls` 定位供应商，必要时 config 上调预生成占比（**此为形态内热开关，≤1 分钟**）。
