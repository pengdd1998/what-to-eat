## 〇、定位升级（一句话）

> **前台决策形态不变（多步选择题 + 选项卡），后台升级为「情境引擎」：LLM 融合外部环境（地域 / 季节 / 天气气温 / 用餐时段 / 附近热销）× 个人口味画像，让选项卡更快收敛到用户需求。**

- LLM 不抢交互层：用户感知到的仍是熟悉的选择题和选项卡，零学习成本，规避"低能量用户连对话都懒"的流失风险；
- LLM 接管生成层：选项卡出现之前的全部理解、检索、排序工作；
- **LLM 是产品成立的前提，不是增强项（v4）**：移除 LLM，产品即退化为 A/B 实验中的"固定选择题"对照组，差异化归零——因此 LLM 能力建设（选型、成本、延迟、评估、降级）按**战略依赖**管理，详见 M0；
- 收敛步数成为核心过程指标：**5–7 步 → 2–3 步 → 0 步（饭点主动推送"今日三张卡"）**，演进模型详见「二、收敛阶梯」；
- 北极星指标维持："被托付的决策次数"（用户把决策交给它、且吃完不反悔的次数）。

## 一、LLM 参与模块地图（按用户旅程排列）

### M0 能力底座：LLM 作为核心能力的依赖全景（v4）

**能力依赖地图**——每个产品功能背后是哪项 LLM 能力在承载：

| 产品能力 | 所需 LLM 能力 | 关键技术要求 | 失败红线 |
|---|---|---|---|
| 情境引擎（M1） | 约束解析、矛盾调和、候选重排 | 出卡延迟 < 2s（点完最后一步到三张卡呈现） | 情境误判且不可纠 → 必须有一键纠偏兜底 |
| 口味画像（M2） | 行为流蒸馏、画像维护、对话式修改 | 字段置信度框架；画像全量可导出 | 画像错误固化 → 衰减机制防范 |
| 说人话回访（M3） | 菜品级方面抽取 | 抽取准确率 > 90%（人工抽检月度复测） | 错误记忆污染画像（一次错记 = 多次错推） |
| 可解释推荐（M4） | 理由生成（情境×画像×事实三源融合） | 每条理由可溯源到真实数据字段 | **编造事实 = 信任崩塌，零容忍** |
| 供给知识库（M5） | 评价/菜单批量抽取、刷单文风识别 | 抽取吞吐与单店成本可控 | 脏数据混入候选池 |
| 收敛阶梯（二） | 字段置信度评估、探索性省略决策 | 硬约束（忌口）永不省略 | 猜错忌口 → 安全事故级差评 |

**LLM 质量工程（核心能力 = 质量即产品质量）**：

1. **评估基准集先于功能建设**：构建覆盖代表性决策场景（天气 × 时段 × 画像组合）的 golden set，每次模型/prompt 升级必须跑回归——LLM 时代没有评估集就上线，等于裸奔迭代；
2. **分层调度控成本**：小模型承接约束解析/方面抽取等高频任务，大模型只用于画像蒸馏和复杂矛盾调和；单次决策 LLM 成本上限纳入单位经济模型；
3. **降级预案**：LLM 服务不可用/超预算时，自动退回"固定选择题"模式（即 A/B 对照组形态）——产品可用性不归零，差异化暂时丢失，事后告知用户；
4. **版本化与可回滚**：prompt/模型版本化管理，画像写入必须经过校验层，升级出问题可回滚而不丢用户记忆。

### M1 情境引擎：选项卡生成的大脑 ⭐核心（v2 修订）

LLM 退居后台，在选项卡出现之前完成全部理解、检索、排序。

**三层收敛公式**：

> **语境先验**（外部环境 → 决定候选池）→ **个性偏置**（口味画像 → 重排加权）→ **当场意图**（选择题答案 → 最终过滤）→ 选项卡

**输入信号清单**：

| 信号 | 来源 | 调制什么 |
|---|---|---|
| 地域 | 定位/IP | 本地菜系与口味基线（南米北面、嗜辣区），候选池的"地缘常识" |
| 季节 | 日历 | 应季品类轮换（秋冬热汤锅物 / 夏季捞汁凉面），防推荐一成不变 |
| 天气/气温 | 天气 API | 冷→暖食汤类加权、热→清爽系加权；雨天→压缩到店半径、提示配送延迟 |
| 用餐时间 | 时钟 | 午餐→快收敛池（出餐快/熟店），晚餐→治愈池（味道优先），宵夜→独立池 |
| 附近热销 | 供给数据 | 供给真实性锚点 + 群体先验，补个人画像冷启动空窗 |
| 个人画像（M2） | 行为流+回访 | 排序偏置：忌口/偏好/近期频率（连吃三顿粉面→降权粉面） |

**产品化要点**：

1. **情境必须可见**：每张卡带一行情境理由（"降温 8°C · 适合热汤"）。看不见的情境会让用户困惑"为什么推这个"，看得见的情境让引擎被感知、误判可归因；
2. **误判必须可纠正**：情境加权只是先验，用户"换一批/不要汤类"一键纠偏，纠偏本身回流为画像信号；
3. **"附近热销"要过信任过滤**：热销单独用 = 重新制造"千人一类"抱怨；必须 **热销 × 个人画像 × 菜品级可信度** 三重交叠后才进候选池（对齐 M5）；
4. **选项卡职责分工（三张卡设计）**：稳牌（画像最优解，大概率复购）+ 新牌（画像邻域探索，防吃腻）+ 应景牌（纯情境驱动，让引擎被看见）——用户认出模式后选择更快；
5. **0 步模式（终极形态）**：画像+情境足够强时，饭点（如工作日 17:30）主动推送"今日三张卡"，在 22 分钟刷外卖开始之前截住痛点——从"拉"变"推"；
6. 对话降级为兜底入口：不愿点选择题的用户可以打字/说一句话，同一引擎解析（原对话方案的残部）。

**采访依据**：病根是选择过载——情境引擎把"收敛"从用户的 5–7 步脑力劳动转移到后台；22 分钟故事发生在傍晚 18:12（时间/天气/疲惫状态都是可获取的情境信号）。

### M2 个人味觉记忆：建模 + 可对话 ⭐护城河
- **原来**：选择快照 + 复购信号 + 三按钮回访，机器读的隐式行为流；
- **现在**：LLM 把原始饮食日志持续蒸馏成**一份自然语言的口味画像**（"偏好酸辣汤粉类，忌油炸，嫌咸，近两周粉面频率过高该换口味"）；
- **关键升级**：画像**用户看得见、聊得了、改得动**（"以后别给我推金针菇"→ 立即生效），不再是黑盒 embedding；
- **采访依据**：抱怨清单最深一条"每次裸奔决策"的完整解法；记忆×LLM 让数据飞轮更陡：记得越多→理解越准→越离不开。

### M3 饭后回访：从三按钮到说人话
- **原来**：踩/一般/爱三按钮（带宽极低）；
- **现在**：随口一句"汤偏咸、肥牛不多，但挺暖"或一张菜品照片 → LLM 做**菜品级**的方面抽取（咸淡/分量/复购意愿），直接入库；
- **交互时长不变（5 秒），信号带宽爆炸**；
- **采访依据**：平台以店铺为单位、用户吃的是"这一餐"——菜品级记忆靠 LLM 抽取才经济可行。

### M4 可解释推荐：杀死反事实思考 ⭐决策闭环
- **原来**：选项卡无理由；
- **现在**：每张卡配一行**三层理由**（情境 × 画像 × 供给事实）："降温 8°C 适合热汤；你上周说过想喝汤；这家'偏咸'提及率仅 8%，距你 800 米"；可展开"为什么不推我收藏的那家"；
- **采访依据**：用户故事结尾"要是换另一家会不会更好"＝无决策闭环，**解释是反事实思考的解药**。

### M5 供给侧：菜品级知识库的批量构建
- **原来**：地图 POI 底库 + 用户众包慢速积累（供给侧是自认的"极大问题"）；
- **现在**：LLM 批量处理公开评价/菜单 → 抽取菜品级属性（口味/分量/油腻度/辣度/招牌菜），并对评价做**可信度过滤**（识别刷单文风、广告探店话术），输出可信摘要（"300 条评价中 12% 提到汤太咸"）；
- **采访依据**：信任崩塌抱怨（刷单/买排名/广告探店）；供给侧缺口拿到了一条便宜的加速路径。

### M6 冷启动：首跑 30 秒对话 + 群体先验
- 首次启动改为 30 秒口味闲聊（忌口/辣度/雷区/预算带），LLM 当场生成画像初版；
- 个人数据空窗期用群体先验补位："和你一样不吃辣、嫌油腻的人，最近吃满意的是……"；
- **采访依据**：冷启动三段论（意图当场交付/行为沉淀记忆/群体补位）全部可由 LLM 承接。

### M7 场景扩展（原边界外，谨慎收编）
- **群聊聚餐决策**：每人跟 LLM 说约束，它居中调和出 3 家候选——"随便"背后沉默的纠结者才是真用户；
- **异地出差**：对话天然适配陌生城市语境；
- **冰箱场景**（拍冰箱→今晚做什么）：用户故事里真实出现过（鸡蛋面条青菜），但跨入做饭赛道，**建议二期再议，不进首版边界**。

## 二、收敛阶梯：步数是画像厚度的函数（v3）

> 飞轮表述：用户用得越多 → 画像越厚 → 收敛步数越少 → 越愿意被托付 → 画像更厚。
> **步数递减不是功能迭代，是数据飞轮的外在表现；反过来，步数不降就是飞轮没转的报警信号。**

| 阶段 | 画像状态 | 收敛步数 | 引擎策略 | 用户感受 |
|---|---|---|---|---|
| **L0 冷启动** | 空 | 5–7 步 | 情境先验 + 群体先验 + 当场意图，LLM 推理扛主力；推荐保守广谱（热销锚点保底），**宁多问一步，不硬猜一次** | "它还不太懂我，但已经比刷 22 分钟强" |
| **L1 学习期** | 基础字段固化 | 3–4 步 | 已知字段从"问"变"默认确认"（"不吃辣已默认 ✓，今天也这样？"） | "它在记住我" |
| **L2 熟练期** | 画像+情境可预测 | 1–2 步 | 只确认当日变量（心情、预算例外项） | "它懂我" |
| **L3 托付期** | 高置信画像 | 0 步推送 | 饭点推"今日三张卡"：一键采纳 / 换一批 / 一句话改约束 | "饭点等它投喂" |

**关键机制设计**：

1. **每一步的双重身份**：早期多步不是缺陷，是刻意的画像投资——每步答案既是决策辅助，也是画像采集。用户多花的每一步，必须在后续以"不再被问"的形式获得**可感知的回报**，否则多步＝纯流失风险；
2. **升级由字段置信度驱动**：画像按字段建模（忌口/辣度/预算带/品类偏好/就餐方式/分量偏好…），字段置信度 = 明确声明 + 行为次数 + 回访信号加权；超过阈值的字段，对应问题从"采集"→"确认"→"省略"；
3. **硬约束与软偏好分级**：忌口/过敏类绝不猜测（每次保底确认，安全优先）；偏好类允许探索性省略；
4. **省略必须显式**："根据你的口味默认了 3 项，查看/修改"。步数骤降不显式会让用户失控（"它怎么不问我了"），省略可见才积累信任；
5. **场景间收敛速度不同**：工作日午餐（高重复性）最先到 0 步；独食治愈场景建议长期保留 1–2 步——"犒劳自己"时，2–3 步的轻引导是被服务的仪式感，不是摩擦。**步数不是全局越少越好**；
6. **画像需要衰减机制**：口味随季节/情绪漂移，近期行为权重高于远期行为，防止画像过拟合成"永远只推那三家"。

**新增风险**：
- **首因效应**：画像薄时 LLM 硬猜导致首周连续推荐偏差 → 直接流失。对策：L0 推荐"保守 + 广谱 + 热销锚点"；
- **画像焦虑**：步数变少会让部分用户惊觉"它怎么这么了解我"。画像可见、可聊、可改（M2）是步数递减的前提。

**指标配套**：分层用户占比迁移（L0→L3）、平均步数 × 使用周龄曲线、**0 步推送采纳率**（＝真正意义上的"被托付"）。

## 三、克制清单：LLM 不碰的地方

| 层 | 归属 | 理由 |
|---|---|---|
| 事实层（店铺存在/营业时间/距离/价格/配送范围） | 确定性数据 + RAG | LLM 编造一家不存在的店 = 一次信任崩塌，致命 |
| 候选集终审 | 确定性过滤引擎 | LLM 只负责理解和解释，不负责"事实裁决" |
| 交易链路（CPS 引流链接） | 纯工程 | 无智能需求 |
| 高频简单调用 | 小模型/缓存/预编译画像 | 控制延迟与成本，日均 1 次决策经不起 10 秒等待 |

**架构总原则：LLM 管"理解和表达"，确定性系统管"事实和交易"。所有生成内容必须 grounded 在真实供给数据上。**

## 四、主要风险与对策

1. **幻觉** → 全链路 RAG + 事实校验层（推荐前逐条校验店铺在营/可达）；
2. **成本与延迟** → 分层模型调度（约束解析用小模型，口味对话用大模型）+ 画像缓存 + 常用约束预编译；
3. **菜名语音识别**（方言/小众菜）→ 食物领域词表 + ASR 后 LLM 纠错；
4. **隐私**（忌口涉及健康/疾病敏感信息）→ 口味画像可查看、可导出、可删除，支持本地化选项；
5. **过度对话化** → "一句话+一键确认"为默认，对话为兜底——对瘫在沙发上的用户，多一轮对话都是流失点。

## 五、落地节奏建议（MVP 切分）

- **P0（验证核心主张）**：M1 情境引擎生成的选项卡 + M4 卡面理由行 + **收敛阶梯 L0/L1 两档**——与"无 LLM 固定选择题版 / 自由刷外卖版"做三方 A/B，核心度量：**收敛步数、决策总耗时、餐后满意度、饭后反事实思考率**（v2 修订：原对话版 A/B 取消）；
- **P1（建立护城河）**：M3 说人话回访 + M2 口味画像 —— 数据飞轮启动，驱动阶梯 L1→L2 升级；
- **P2（供给侧长跑）**：M5 菜品知识库 + 评价可信度过滤；
- **暂缓**：M7 场景扩展（群聚餐/冰箱），验证主场景后再议。
