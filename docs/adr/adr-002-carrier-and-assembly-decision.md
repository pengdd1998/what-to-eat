## 四、决策记录（ADR-002）

**状态**：已接受（Accepted）——附带 W1 守门验证条件（见"重新评估条件"）。

**背景（关键数字）**：种子用户 30–50 人、全周期会话 120–150、n≈30 会话/周（NFR 2.2 v3）；峰值 QPS ≤1、并发会话 ≤10（NFR 2.1 v3）；核心时段 17:00–21:00 可用性 ≥99%、全周期累计停机 ≤70 分钟、RTO ≤4h、RPO ≤24h（NFR 2.3 v3）；埋点 <1 万条 / <100MB；回访应答 ≥40 条、依从 ≥30%（止损线 <20 条）；总工程量 ≤6.5–7 人周、1 人 + AI（H2）、窗口 8–9 周含缓冲（H1 v3）；硬约束 H3（零身份信息）/H4（服务端零 POI）/H9（Docker）；开发者画像**强 Python、弱 JS（已确认，非假设）**；三大不确定点 R1（外卖可得性数据路径）/R2（深链探活×口径耦合）/R3（载体未决，牵动触达/埋点/发布链三子系统）；第二轮初筛 A、E 保留，B（云开发，违反 H9）/C（微服务，违反 H2/H1）/D（SaaS 拼装，结构性缺失 FR-09/11/12/13）淘汰。

**候选**：A（微信原生小程序 + Node/Go 自建单体）、E（Vite 静态 H5 + 自托管开源组件单体）。

**决策**：**选 E 为主方案**。加权总分 79.0 vs 62.0，差 21.5% ≥ 15%，未触发延迟决策条款，当期拍板。E 的落地面含一个待闭合子决策：薄自研 API 的栈（ADR-001 的 A vs B′，即 U1′）——保留原延迟决策流程（D8 探针 / B′ 骨架 PoC / 统计对决赛），W1 周五死线不变，重拍结论落 **ADR-003**（占用实施方案 U1′ 所指的编号）。

**理由（逐条对应背景）**：
1. **对 H2/H1（6.5–7 人周、8–9 周）**：E 保留 0.5–1 人周净余量且薄 API 可落 Python；A 顶格 H2（订阅消息 +2D + 审核流程设置），任何超支直接击穿窗口。
2. **对 M2 周迭代与 n≈30 会话/周的稀缺性**：E 发布链全自控（分钟级发布/回滚、双版本 ≤1 分钟直达 B-06）；A 的代码级修复受审核门控，1–7 天延迟 [假设] 在会话不可重放的前提下等于数据周永久损失——config 通道只能免除"迭代"发版，免除不了"修 bug"发版。
3. **对 H3/H4/NFR 2.4**：E 零平台身份（openid 问题不存在）、Web JS API + 域名白名单为 H4 合规最优位；A 以 openid×H3 的合规张力换取订阅消息触达，从严口径下该交换归零（回访仍退化为次日自报）。
4. **对画像（强 Python、弱 JS）**：前端 JS 税两候选恒定，E 的薄 API 可落 Python 而 A 锁死 Node/Go——D8 差 2 档是结构性的。
5. **对 R3（载体未决）**：E 本身就是 R3 的"H5 分支"原位答案；其"小程序分支"吸收方式（API/UI 分层，未来可加薄壳）已在实施方案 §1.1 预留——选 E 不关闭未来载体切换的门。

**落选者否决理由**：
- **A**：非能力否决，是结构性否决——发布链外部门控 × 会话稀缺不可重放（D3）、openid×H3 张力使其核心差异化（触达）以合规风险换取且从严即归零（D5）、全栈正面顶撞已确认画像（D8）、小程序资产不可携 + 下周期 LLM 方向需 Python（D10）。与 ADR-001 对 Java 的排除同理：**排除是"约束 × 画像"的函数，不是小程序本身的缺陷**；若画像为"强 JS/微信生态"、审核实测 ≤3 天且 openid 口径宽松，A 应反超（见第五节翻案条件）。

**后果**：
- **收益**：M1 构建按 W1 死线启动（与既有实施方案 E1 兼容，U1′ 流程直接复用为薄 API 栈决策）；发布/回滚/双版本切换三项 NFR 2.5/B-06 指标全自控；合规要件（H3/H4/H6、B-07/B-09）无平台身份黑盒；8 周后若按 LLM 研讨稿续期，Python 薄 API 与数据资产可直接延续。
- **代价**：放弃订阅消息推送 → 回访依从承压（E-R3，M3 ≥40 条目标的达成风险由"推送"改由"次日自报 + 群内人肉轻推"承担）；Umami 双链路税 ~0.5–1 人日（E-R2）；微信 webview 标识持久性需实测（E-R1）。
- **新增风险与缓解**：①webview localStorage 不持久 → D-15 退化判据 + 占比告警；②Umami 字段丢失/税超支 → PoC-2 预验，超线即组件级降级自研 ingest（不换载体）；③回访 <20 条 → 联动产品 M3 止损（P3 关闭），下周期载体重评。

**重新评估条件（信号或时间点）**：
1. **双信号同时成立 → 差距落入 <15%，触发延迟决策条款**：①载体 spike（T0.3）实测小程序首审 ≤3 天且类目路径可行（A 的 D3 3→4）；②openid 获"不属身份信息"书面合规口径（A 的 D5 3→4）——两项均落则 A=68 vs E=79，差 13.9%，须按第五节流程以 PoC 数据重拍（拍板人 = 本人）。
2. **E 侧双降触发接近**：Umami 双链路税 >1 人日或关键字段丢失（D1 4→3）且 webview 实测清除（D4 3→2）→ E=73 vs A=62，差 15.1%，边缘，重开评审。
3. **信号**：P0-3/R1 spike 若发现外卖平台数据路径仅小程序载体可得（如店铺列表仅小程序侧可取）→ 载体重评。
4. **信号**：M3 回访应答 <20 条且归因为"无推送"→ 下周期立项时载体重评（本期止损联动）。
5. **时间点：8–9 周窗口结束**——本决策仅对本期实验负责，下周期按 M3 实测数据与 LLM 研讨稿重新评估。

## 五、接近判定、敏感性与（若触发的）延迟决策安排

**是否接近**：79.0 vs 62.0，差 17.0，相对差 **21.5% ≥ 15% → 不接近，当期拍板 E**。

**敏感性披露**：全表唯一能翻案的组合是 A 侧两个**从未实测的平台判断**——审核速度（D3）与 openid 合规口径（D5）。两者同时利好 A 时差 13.9% < 15%（触发重拍）；单一利好均不足以（D3 单升 → 16.3%；D5 单升 → 17.7%）。E 侧双降（Umami 税超支 + webview 失败）可把差距压到 15.1% 边缘。

**若触发，延迟决策安排如下**：
- 并行执行：A-PoC-1（3 天，提审实测）+ A-PoC-2（1 天，openid 书面口径）+ E-PoC-1（3 天，webview 持久性）+ E-PoC-2（1.5 天，Umami 双链路税）——四项合计 ≤3.5 人日，在 W1 载体 spike（T0.3，1.5D）预算内合流，不新增窗口。
- **哪个判断最可能错**：
  - E 的最可能错判断：D4=3 对 webview 标识持久性偏乐观——微信 webview 清存储的历史行为随版本漂移，30 天窗口的 3 天实测外推可能失真；反向则 D6=3 也可能低估 Umami（其自定义事件上限与导出完整性近年持续改善，旧结论出自 ADR-001 对"问卷引擎+Umami 全托管"形态的评估，与"仅作原始接收"新用法不同）。
  - A 的最可能错判断：D3=3 对审核偏悲观——个人主体工具类小程序近年多为"数小时级"秒审 [假设]，若属实 A 的最大减分项消失；反向则 D5=3 也可能高估（openid 从严几乎必然，平台伪标识在个保法实践中小多名案均按"可识别自然人信息"处理 [假设]）。
- **最终拍板人：本人（1 人团队的产品与工程 owner）**——AI agent 提供评分、PoC 数据与证伪分析，不持有拍板权；拍板时点 = W1 周五前（M1 构建启动前，与 H1 一致）。
