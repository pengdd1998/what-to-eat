# ADR-004｜LLM 供应商接入：小米 MiMo（mimo-v2.5）

> 状态：**已接受（2026-09-03，本人拍板并提供 API key）**——U2 供应商分叉闭合；两项预算值（单次成本上限、熔断阈值）待控制台实测校准后收紧，PIPL 出境评估结论随本文落档。

## 背景（关键数字）

- 用途双路径：**批产**（周更池/菜库文案，离线，无延迟硬约束）＋ **A 形态冷启动实时**（P95 ≤3s、硬超时 6s，评审 #7）
- 成本红线：SC-2 ≤$50/月（月累计 >$40 触 P2 降级预备）；SUP-03 日调用/日费用双熔断
- 合规：偏好数据经 LLM 传输须脱敏（标签＋匿名摘要＋假名，不传 anon_id 原文）；PIPL 出境评估随供应商定稿闭合（X1）
- 已有事实：本人已注册小米 MiMo 开放平台并持有按量付费 key（sk- 前缀）；早前 PoC-2 首份文案即由该平台产出（供应商一致 → **不触发 ADR-003 评审 3 的"定稿≠PoC-2 模型"重评**）

## 候选方案

1. **小米 MiMo `mimo-v2.5`（选定）**——key 已有、中文口语文案质量实测达标、按量计费起步成本≈0
2. 智谱 GLM / 通义 / DeepSeek 等国内主流 OpenAI 兼容供应商 [未询价未测——[推测] 否决理由：需新注册/充值与选型工时，W1 窗口内 MiMo 已满足双路径实测门槛]
3. 双供应商抽象的第二个实现（ADR-003 RSK-2 预案的组成部分）[推迟：接口已预留（provider 配置驱动），单供应商期不建冗余——[推测] 否决理由：HC-1 预算，触发条件见重评]

## 决策结果

`config.llm = {provider: "openai_compatible", model: "mimo-v2.5", disable_thinking: true}`；key/base_url 仅存 `.env`（gitignored，SUP-02）。

## 理由（逐条对应背景）

1. *P95 ≤3s* → **实测**：默认思维链 7.97–21.28s（4 次采样全部超 6s 硬超时）；`thinking:{"type":"disabled"}` 后 1.38–2.85s（PoC-4 探针 12/12 成功、P95 2852ms、错误率 0%）——关思维链是实时路径成立的硬前提，已固化为 config 默认值
2. *批产无延迟约束* → 10 菜批产形态 5.5s（关思维链）/34.5s（开），质量均达标；批产可按需开思维链
3. *SC-2 ≤$50/月* → MiMo V2.5 系已宣布永久降价（官方，最高降幅 99%）[假设：具体单价以控制台为准]；保守成本参数 0.01 美元/次先挂熔断，控制台出账后校准
4. *PIPL* → 小米为境内供应商、境内端点（api.xiaomimimo.com），无出境传输 [待确认：本人复核平台数据条款一句]

## 实测依据（PoC-4，2026-09-03 08:40，非核心时段）

| 形态 | 配置 | 耗时 | 结果 |
|---|---|---|---|
| 实时单菜 ×12（适配器全路径） | thinking off | P50 ≈1.4s / **P95 2.85s** / P99 2.85s | 12/12 ok，错误率 0% |
| 实时单菜 ×4（裸调用） | thinking on | 7.97 / 21.28 / 13.41 / 1.38*（*为 chat_template_kwargs 变体） | 3/4 超硬超时 |

| 模型探测 | — | `mimo-v2.5-flash` 不存在（400）；`mimo-v2.5-pro` 32.4s（推理 1475 字） | 仅 `mimo-v2.5` 可用且达标 |

**注**：正式判读口径要求 19:00–21:00 核心时段复测一轮（W2 D1 前补）；非核心时段通过＝方向性证据。

## 否决理由

- **flash**：接口 400 Unsupported model（实测）
- **pro**：推理链过长，32.4s，实时路径不可用；批产可用但成本高于 v2.5 [推测：定价分档]
- **其他供应商**：[推测] 见候选 2——W1 窗口与已持 key 的事实使 MiMo 为最小阻力路径；质量/延迟实测均已过关，无必要横向比价

## 后果

- **收益**：U2 供应商分叉闭合；X1 就绪；A 形态实时降级链端到端可用（池未命中→实时→菜库）；PoC-2 配对版文案当日产出（判读基础补齐）；批产管道可换真实生成（T1.5 下一步）
- **代价**：单供应商依赖（RSK-2 预案的接口已预留，双实现未建）；思维链关闭后复杂约束调和能力下降 [假设：10 标签多约束场景质量待 M1 狗粮期校准]
- **新增风险与缓解**：①按量计费失控 → 双熔断已在适配器（日 200 次/日 $1.5 [待校准]）＋llm_calls 全量留痕＋cost_close 日结；②key 泄露 → 仅 .env（gitignored），建议本 key 若曾在其他渠道粘贴则择期在控制台轮换；③思维链参数为小米私有扩展 → 适配器已按 config 开关隔离，换供应商不受锁

## 重新评估条件（信号或时间点）

1. 核心时段（19:00–21:00）复测 P95 >3s → 实时路径降级评估（池预扩容上调，ADR-003 条 4 联动）
2. 月成本 >$40（SC-2 降级预备线）→ 预生成占比上调或换供应商
3. M1 狗粮期不可接受率 >30% 且归因生成质量 → 开思维链批产 vs 换供应商评审
4. MiMo 平台模型下线/改价 >3× → 重开供应商选型（候选 2 复活）
5. 本人复核平台数据条款发现出境/共享条款异常 → PIPL 重评并触发 X1 重审

## 附录：候选 2 市场情报补全（2026-09-03 检索，供重评条件 1/4 触发时使用）

- **阿里通义 qwen3.8-flash（百炼）**：[假设·媒体口径] 价格低于 DeepSeek V4-Flash，官方定位"效果接近旗舰＋降成本"；短文本快速响应为其强项；OpenAI 兼容、境内、思维链可控（enable_thinking）——**推荐为第二供应商首选**（RSK-2 双供应商抽象的第二个实现，W2 前注册 key 备用即可，代码已配置驱动无需新写）

- **智谱 GLM（2026-09-03 09:xx 实测，本人账户免费档）**：

## 附录：收敛性基准（2026-09-03 深夜，owner 指定的供应商裁决维度）

> 任务设计：以夜 2 真实会话为 ground truth（30 场分层样本，10 菜 ×3；用户 tags/状态 → 实际接受的菜），令两家对**同一 10 菜池**（附各菜适配标签）做前三排序（temperature=0.3，生产 A 形态"池排序"同构任务）；rank=命中用户真实选择所需步骤（1=首推即中/0 换一，4=换一耗尽未中）。

| 维度 | MiMo mimo-v2.5 | qwen3.8-flash | 优胜 |
|---|---|---|---|
| 首推即中（rank1） | 27/30 = 90% | **30/30 = 100%** | qwen |
| 3 步内收敛（换一上限内） | 30/30 = 100% | 30/30 = 100% | 平 |
| 平均收敛步骤 | 1.17 | **1.00** | qwen |
| 调用时延 P50 / P95 | 2311 / **3322ms** | **1011 / 1241ms** | qwen（2.3×/2.7×） |
| tokens/次 → tokens/收敛 | 321 → 375 | **303 → 303** | qwen（−19%） |
| top1 标签重合率（副指标） | **96%** | 89% | MiMo |

- **关键事实**：① MiMo 未命中的 3 场全部集中在「香菇滑鸡煲仔饭」分层（3/3 全 miss，top1 均给照烧鸡腿饭——同为预算向但非用户实际选择）；qwen 10 分层全对。② **排序任务（长 prompt）下 MiMo P95 3322ms 破 3s 预算线**——与单文案任务（P95 2501ms）不同任务形态，晚高峰真实压力下 A 形态实时路径用 MiMo 存在超时风险；qwen 余量 2.4×。③ 费用维度在本项目用量级不构成区分项（ADR-004 §2.3：实时路径 ≈80 次/周，flash 档全月个位数元级；tokens/收敛 qwen 仍低 19%）。
- **建议（按 owner 指定维度裁决）**：**qwen3.8-flash 六维度四胜一平一负（唯一负项为副指标标签重合率，且其实际命中用户选择 100% 更硬）——建议换 qwen 为主供应商、MiMo 降为第二**。待本人拍板；config 切换 ≤1 分钟（双供应商抽象就绪），批产与实时同步切。
- 披露：本轮基准前有一轮脚本 bug（响应解析 AttributeError）导致 60 次调用发出后未采到数据即失败——两家各 ~90 次真实调用累计成本仍为分/元级（flash 档），已如实入账观察。

## 决策修订：主供应商切换 qwen3.8-flash（2026-09-04，owner 拍板）

- **拍板原话**：「文本模型选用qwen」。
- **依据**（本 ADR 附录三组数据）：①晚高峰复测延迟可用性全指标占优（P95 2.20s vs 2.50s，12/12 vs 11/12）；②**收敛性基准**（owner 指定维度）：首推即中 100% vs 90%、平均步骤 1.00 vs 1.17、排序任务 P95 1241ms vs 3322ms（MiMo 破 3s 线）、tokens/收敛 −19%；③两轮文案质量均达标（PoC-2 q 臂留档）。
- **新格局**：主供＝**qwen3.8-flash**（百炼兼容模式，enable_thinking:false）；**MiMo mimo-v2.5 降为第二供应商**（env 备选位保留，双供应商抽象就绪）。
- **落地**：①llm_gateway 关思维链参数按厂商分派（qwen→enable_thinking:false；其余→thinking.type=disabled）——已实测适配器路径 3/3 ok＋llm_calls 留痕；②CONFIG_DEFAULTS llm.model=qwen3.8-flash；③**生产切换随 9/8 发布窗**：服务器 .env LLM_BASE_URL/LLM_API_KEY 换 qwen 值＋Admin config llm.model 翻转（ensure_config 不覆盖存量 config，须显式改）＋重启后探针复测。
- 本 ADR 标题保留 MiMo 命名（历史决策链完整）；后续引用以本节为准。
