**差距判定**：前两名 C 85.0 与 A 84.3 相差 **0.7 分（0.8%）＜ 15% → 接近**，触发延迟决策条款；第三名 B 距 A 19.8%、距 C 20.5% ≥ 15% → 不属接近，即时否决。

**敏感性与翻案披露**：修订前（D8 未计画像）A−B＝15.2% 恰在阈值边缘；计入画像后 19.8%，否决稳固。B 的翻案组合仍存在：若 W1 spike 同时证伪其两个低分格依据（beacon 到达率 ≥95% 且实时 P95≤3s，即 D2 6→9、D3 6→9），B＝75.1 vs A＝84.3，差 10.9%＜15%，按接近条款重开延迟决策流程（见"重新评估条件"）；但 D8 的画像事实不可被 spike 证伪，B 的复活须额外跨越画像劣势。

## 四、决策记录（ADR-003）

**状态**：已接受（Accepted，附条件）——B/D/E/F/G 否决即日生效；A 与 C 总分差 0.8%＜15%，依评审规则 3 不以总分定夺，**主方案推迟至 W1 周五 PoC 闸门终裁**；A 为领先候选，C 为对照候选兼 HC-2 法定兜底。终裁结论回写本文档附录后本 ADR 方为终态。

**背景（关键数字）**：8 周总窗口（2026-09-02 起）；总投入 ≤8 人周（构建 6.5＋缓冲 1.5）、1 人＋AI；M2 峰值 QPS<1、M3 按 500 用户 [假设] 峰值 QPS<10；LLM ≤$50/月 [假设]；验收 ≤30 秒/≤5 步、生成 P95≤3s、首屏 P75≤2s；核心时段可用性 ≥99%/月、RTO≤4h、RPO≤24h；8 周 <50 万埋点事件、<1GB；北极星＝双事件 60 秒窗口（服务端时钟判定，SUP-06）；M4 闸门 ≥2.0 go / <1.0 stop；开发者画像强 Python 弱 JS（已确认）；加权总分 A 84.3 / C 85.0 / B 67.6。

**候选**：A（PyThin——Python 薄 API 单体·静态池为主）、B（NodeRT——Node 单体·实时生成为主）、C（RuleFloor——规则引擎＋本地菜库）深评；D（小程序）/E（云 BaaS）/F（微服务）/G（外卖 CPS）初筛淘汰，不复活。

**决策**：
1. **B 否决**，其"实时生成编排＋双供应商熔断"设计降格为 RSK-2 预案，以模块级方案保留在 A 骨架中，不作为独立候选；
2. W1 内执行三个判读性 PoC（池命中率/规则空集联合仿真、模板 vs 生成文案对照、302/beacon 真机 spike，见第五节）；
3. W1 周五 ADR-001 评审会由本人终裁 A 或 C；逾期未裁 → HC-2 条款自动执行，落 C；
4. SC-1 语言分叉随终裁闭合：A 胜出 → 语言即 Python（TS 形态候选已被 D8 画像与 D1 工时证据排除）；C 胜出 → 语言按画像落 Python。两种结局均闭合 SC-1，无需另立栈 ADR。

**理由（逐条对应背景）**：
1. *8 周/≤8 人周/W1 周五死线* → B 携三个额外工作包、自评已贴 6.5 人周顶（D1=6 全表最低格之一），距前两名 ≥15%（19.8%–20.5%），不属"接近"，可即时否决；其一年期人力最差情形（17.5 人周）是三家中唯一可能突破 HC-1 者。
2. *"统计结论是唯一交付物"＋60 秒双事件* → B 默认路径把北极星分子押在未证实的 beacon 机制上（D2=6）；A/C 的 302 跳板是确定性记功解——此为否决 B 的第二支柱。
3. *画像强 Python 弱 JS（已确认）* → B 全栈 TS 与画像正面冲突（D8=6），AI 产出可代工构建、代工不了本人验收与 webview 排障——此为否决 B 的第三支柱，且该事实不可被 spike 证伪。
4. *加权总分 84.3 vs 85.0（差 0.8%）* → 触发规则 3。C 的领先集中在结构性占优维度（进度/成本/合规 9–10 分），A 的领先集中在保真与生态——真正分歧点（D4：7 vs 5）恰是 PoC-2 能在 ≤3 天内以可观测标准分辨的判断，故推迟而非掷于总分。
5. *QPS<10、<1GB、RTO≤4h* → 三家容量与运维均非瓶颈（D6：9/7/9），不构成裁决依据，避免以伪差异定夺。
6. *SC-5 闸门（首推接受率 ≥50%、北极星 ≥2.0 go/stop）* → 保真度失误比工时超支更不可逆：形态若测不出真实假设，M4 判读整体失真——这是 A 不因 C 的总分优势被直接压倒、保留终裁资格的核心理由。

**落选者否决理由**：
- **B（67.6）**：距前两名 19.8%–20.5%；三支柱——①D1 工时贴顶且最差情形破 HC-1（14–17.5 人周/年）；②D2 beacon 敞口正对 HC-7 唯一交付物；③D8 全栈 TS 顶撞已确认画像。翻案组合与门槛见"重新评估条件"。
- **C（85.0）**：**未否决**——进入 W1 周五终裁，并兼任 HC-2 法定兜底。
- **D 小程序原生**：违反 HC-3（载体锁定 H5 微信 webview 且"必须复用"；Umami 无小程序 SDK 同触 HC-3）。
- **E 云托管 BaaS**：违反 HC-3（Supabase≠SQLite、云分析≠Umami 自部署）＋HC-8（无 Docker 自部署形态）；PIPL 数据驻留为加重项。
- **F 微服务/平台化**：违反 HC-1（1 人＋AI、≤8 人周、RTO≤4h 容纳不了多服务运维）；Postgres/Redis 连带触 HC-3。

**后果**：
- *收益*：主方案决策落在两个可观测实验而非 30 格主观加权上；A/C 共享约 80% 组件（SQLite、Umami、跳板、复算、限流、热更配置），W1 骨架投入在任一结局下不报废；推迟有 HC-2 死线硬边界，不会无限悬置；SC-1 语言分叉一并闭合，原 T0.5 双栈骨架对决赛可缩减为单栈走查（回线内，省 ~1.5 人日）。
